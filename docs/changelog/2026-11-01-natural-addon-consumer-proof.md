# Natural add-on notifications across the complete table roster

The existing continuity certificate excludes add-on periods. An explicit
`run-post-deploy-e2e` payload with `natural_addon_tournament_id` and the full
`engine_sha` now selects a bounded consumer observation in the same live-table
lane, using its reserved zero-balance spectator account and mandatory cleanup.
Other observation modes cannot be combined; default certificates are unchanged.

The observer requires a complete exact-count roster of one to eight tables
before the natural window begins. It never truncates the roster or drops a
closed/consolidated table from evidence. Changed rosters, missed/absent windows,
and missing public notices refuse proof. Every table must render the natural
price, chips and advancing countdown; a closed observer is reopened and reloaded
inside the same minute to verify late-open and reconnect, without exceeding the
connection cap. Every notice must close, and engine SHA/instance must remain
unchanged. HTTP and socket participation requests are refused before forwarding.
No events, hands, wagers, purchases or registrations are injected.

Artifacts contain public board/window/roster data, rendered notice captures and
sanitized protocol type names. This proves served spectator consumers, not every
participant device's acknowledgement. Full sixty-second no-hand overlap and
post-window natural hand resumption remain separate SQL evidence. The opt-in
never awards the unrelated full live-table certificate.
