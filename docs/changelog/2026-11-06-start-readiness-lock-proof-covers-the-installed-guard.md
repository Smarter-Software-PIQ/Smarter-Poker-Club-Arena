# Start readiness lock proof covers the installed guard

The required native start-lock test stopped at the superseded September 29 function. It proved foreign-key compatibility but still required every unguaranteed start to serialize on a bank, the behavior that expired Spin and Sit & Go leases on October 2. The installed October 2 guard only takes that lock for an enforced prize or seat guarantee.

The same native route now reproduces the unnecessary club and union waits on its historical image, installs the exact maintained October 2 readiness function, checks its installed definition digest, and runs sixteen concurrent lock assertions. Unguaranteed starts neither wait for nor retain either bank and do not serialize with one another. Enforced guarantees and satellite seat promises still serialize; foreign-key holders remain compatible; unenforced guarantees do not acquire bank locks. Historical overlay debit tests retain their original inputs. The new cases isolate the readiness trigger and do not certify the full current overlay or launch transaction.

The new unguaranteed-start assertion failed against the old guard and all native cases passed with the installed guard. Two initial cluster starts were refused by the macOS Unix socket path limit before assertions; shortening the private socket directory to `s` resolves that portability issue without changing database durability or test budgets. Existing required accounting shard 3 already executes this harness, so no workflow change or new runner is needed. No production code, money operation or migration changes.
