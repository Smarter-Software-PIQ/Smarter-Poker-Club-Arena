# Style options receipt a changed action, and read receipts count once (2026-11-15)

Until now every per-decision style receipt fired when a read was made or an input moved, not when the committed action changed, and some fired twice in one decision (audit C, section C items 6 and 7: the same bettor read at two places, and the deep second look running with telemetry off through receipts that are not telemetry-gated).

- **Action-change receipt.** When an option that is ON applies a non-neutral adjustment in a FAST decision (HorseStyleShadow.noteStyleOptionApplied at each consumer: big-bet honesty and the river bluff-catch cap, raise respect, value raise respect, tight opener and re-raiser respect, fold bluffing, value extraction, the value-bettor maniac call-down; and the two tight-player responses when they ship), the worker decides the same request once more with that one option off: same RNG position, committed governor scale, counters suspended, observation off, no shadow list, Horse-memory effects discarded. One applied option per decision, picked from the decision key. The decision carries the journal field `styleActionReceipt` (option, applied list, changed, actual, without), and `<option>_changed_action_seen` (snake case, for example `style_fold_bluff_changed_action_seen`) is counted once when the final action or amount differs. Deterministic, so the runtime replay re-derives it: the journaled record replays exactly with the receipt.
- **Once per decision.** The read-time receipts `style_fold_bluff_seen`, `style_value_extraction_seen`, `style_value_bettor_not_maniac_seen`, `style_pre_repair_fold_rate_discounted_seen`, `style_read_released_seen`, `style_long_participation_seen` and `style_label_*` count at most once inside a FAST decision's fire scope, and not at all in the deep second look or a re-decision (BrainTelemetry.withOncePerDecisionReceiptsSuppressed). Other counters are unchanged.

No decision changes: the committed action, amount and RNG position are those of the same request with the receipt machinery inert (worker tests with a scripted brain and with the production brain).

Latency (fixed block of 2,340 decisions, the shared style contexts plus checked-to spots, six villains, cash and tournament, seeds 1 to 15, every style option on, the Mac shared by other builders at load 24 to 40): decision p50 1.30 ms before, 1.31 ms after; p99 6.96 ms before, 8.24 ms after; the 390 decisions that applied an option: p50 2.49 ms, p99 9.58 ms with the re-decision. Inside the 15 ms shadow re-decision budget and far inside the 2,000 ms minimum decision deadline, so no sampling.

Limits: the fold-rate pre-repair option and the value-bettor read inside HorseMind.readExploit apply inside HorseMind and are not in the applied registry, so they are re-decided only when another site notes them. The DEEP second look carries no action-change receipt (the FAST look's receipt stands for the decision).
