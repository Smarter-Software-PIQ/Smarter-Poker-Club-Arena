# Backup seat proof binds the frozen window

Backup swap trial 42301511441 compared seat identities before its two-minute announcement with identities after resumed play. A recorded departure at 22:11:39 UTC occurred before the actual 22:13:11–22:18:11 freeze, so that comparison could refuse a correct swap. The durable maintenance receipt recorded successful thaw and 30 resumed tables; the old trial did not retain its fingerprints, so complete historical custody is not inferred from that receipt.

Swap and break trials now capture the frozen predicate, ownership token, start/release boundaries, seat count and identity fingerprint in one SQL statement after freeze. Swap requires the candidate to present the same still-frozen boundary after boot. Existing bounded thaw polling compares each frozen sample. The final proof also requires the same token's v3 release target, a successful maintenance log at that boundary, and no recorded seat exits inside the frozen interval. The v3 preparation timestamp is not treated as release. Failed capture, changed ownership or identities, unreadable queries, an already-thawed post-boot snapshot, and missing release evidence refuse the trial. Existing drain, boot, thaw and dealing checks remain. Trial JSON retains the original, post-boot and last verified frozen snapshots. Table-kill behavior is unchanged.

The existing DR suite executes both trial paths with legal pre/post-freeze activity and invalid frozen evidence. Disposable PostgreSQL 17 qualification executes the actual snapshot queries, validators and receipt query against minimal tables and a controlled freeze predicate: the original interval falsely differs, corrected boundaries pass, actual frozen seat mutation and unreadable capture fail, and wrong-token, missing-successful-log and frozen-exit receipts fail. These are finite sampled custody checks, not a proof against every transient move or qualification of the engine's freeze implementation. No locks manufacture preservation; no live host or production rows were changed.
