# A Horse option can run in shadow (2026-11-18)

Offline leagues play a simulated field, and one human is most of the real data, so a switch is judged against real people before it is flipped. A non-style option can now be switched to `shadow`: the live decision is made exactly as with no row (the option passes nothing to the brain, so the release default acts), and the decision worker re-decides the committed decision once with the option flipped, from the same RNG position, and records what would have changed. Nothing is ever acted on. Nothing is switched to shadow by this change.

- **Which options.** `OPTION_SWITCH_SHADOW_NAMES` (150 today): every registered on/off option that is not off-only, whose release default is plainly on or off (not `code`, where the flipped value is not known), and whose read is per decision (`OPTION_SWITCH_SHADOW_REFUSED`: the fixed-limit probe process switch, the V31 loader serving switch, and the two options whose evidence the observer reads carry only when on). The seven style options keep their own shadow arm.
- **The re-decision** is the style action-receipt mechanism (`workerRuntime.optionShadowReceipt`): committed governor scale, counters suspended, once-per-decision receipts suppressed, observation off, Horse-memory effects discarded, RNG and per-decision registries restored. One option per decision (rotated by decision key); never with work queued, never once the decision spent the 15 ms budget, never at a moved governor scale, and at most `HORSE_OPTION_SHADOW_PER_MINUTE` (default 12, 0 stops it) re-decisions per worker per clock minute. Every skip is counted.
- **The receipt.** Journal field `HorseDecision.optionShadowReceipt` (option, flipped value, changed, actual and counterfactual action and amount, street, variant, format, person dealt in, person still in) and counters `option_shadow_<option>_<changed|same>_seen` plus the person-present subset `..._person_seen`. Exact replay does not compare the receipt (it is rate-budgeted by the clock), as for the style action receipt.
- **Reading it.** `scripts/sql/horse-option-shadow-summary.sql` (daily counters, person-present vs Horse-only) and `npx tsx server/scripts/horse-option-shadow-summary.ts <journal copy>` (action pairs, street, variant).
- **Database.** `20261119054407_the_horse_option_switch_tells_style_options_by_name.sql` makes the four switch functions tell the style options by `canary` instead of `shadow` (no answer changes today); without it a non-style shadow option would skip the citation and evidence rules of `on` and break the style read. The list follow-up `20261119054446_horse_option_switch_shadow_options.sql` (generated) accepts `shadow` for exactly the shadow options and refuses to install before the first file. Neither is installed by this change.

Proof: the acted decision, RNG positions and plan effects of every recorded FAST decision of the phase 6C journal sample are those of no row with the production brain, for options on and off by default; off, on and no row run no re-decision. One re-decision cost p50 1.24 ms over 16 on the shared Mac. The PostgreSQL 17 proof installs the switch migrations in version order and checks shadow for every listed option and its refusal for every other.

**Order of operations.** Install both migrations, and have the engine release that carries this change live, before writing any `shadow` row: an older engine reads a non-style `shadow` row as an invalid configuration and returns every switched non-style option to its release default.
