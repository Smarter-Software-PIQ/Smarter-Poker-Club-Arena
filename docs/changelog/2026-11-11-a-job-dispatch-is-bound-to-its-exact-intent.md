# A job-token dispatch is bound to the exact intent its trusted sender recorded

2026-11-11. Owner direction: a caller that cites a recent legitimate sender run is not
authorization. Each privileged receiver must bind the exact event, repository, sender
workflow, sender head SHA, operation and inputs, and must refuse a replay or a substituted input.

## Mechanism

`scripts/ci/dispatch-intent.mjs`.

- **Sender (`write`).** Before it dispatches, the sender writes `<nonce>.json` for each dispatch. The file records:
  - the operation;
  - the exact inputs;
  - the repository;
  - the sender workflow path, run id, attempt, head SHA and event;
  - a random 128-bit nonce.

  The sender's own job uploads these files as the artifact `dispatch-intents-<run_attempt>` of that run. It then sends the exact body `write` returned. Only the sender workflow's reviewed code can upload to its own run.

- **Receiver (`prove`).** This is the first step of every job that admits `github-actions[bot]`. The receiver fetches the script at the run's own `$GITHUB_SHA` through the contents API and reads the payload from `GITHUB_EVENT_PATH`. It refuses the dispatch unless all of the following hold:
  - this run is the named receiver workflow, event and action;
  - the cited sender attempt is the operation's sender workflow, in this repository, for an allowed event;
  - for any sender event except `pull_request_target`, the sender ran on `main` with a head that `main` contains (`pull_request_target` always runs default-branch code; its head is the PR head);
  - that attempt owns exactly one unexpired `dispatch-intents-<attempt>` artifact, carrying the run's id and head SHA, and that artifact holds `<nonce>.json`;
  - the intent names this operation, repository, sender path, run, attempt, head SHA, event and nonce;
  - every input equals the intent exactly, and no other input is present;
  - this is attempt 1, its display title (the run-name carries the nonce or the sending attempt) is the expected title, and no earlier run of the receiver workflow since the sender started carries that title. A second dispatch citing the same intent is therefore refused.
- The artifact is read as data only. The receiver extracts one member with `unzip -p`, caps its size and parses it with `JSON.parse`. Nothing is executed, imported or interpolated.
- A person's dispatch from the UI or `gh` (any user as triggering actor) skips the step, as before. A person's re-run changes the triggering actor to that person, so it is also admitted.

`tests/unit/aJobTokenCannotStartTrustedWork.law.test.ts` pins every row. It also pins that no
workflow keeps `dispatcher_run_id` or an age window, and that each sender uploads
`dispatch-intents-${{ github.run_attempt }}`. `tests/unit/dispatchIntent.test.ts` covers
substitution, added and missing inputs, replay, a wrong workflow, branch, repository or event,
a forged record, a second attempt and a wrong title.

Residual: the listing used for the one-time check is eventually consistent. Two dispatches
created in the same instant could each miss the other. The applier serializes on its own
queue and the post-deploy and backup receivers serialize per engine SHA, so the window is
the listing lag only. A replay also first needs a write-scoped job token, which the paths
below withhold from untrusted code.

## Review follow-up (2026-11-11)

- **The sender head is the PR head.** For `pull_request_target`, `GITHUB_SHA` is the base tip, not the merged pull request. The intent now records the pull request number and its head, and the receiver fetches that pull request and requires it merged into the default branch from this repository with `head.sha` equal to the sender run's `head_sha`. Every other sender binds the head of its own run (`gto-recheck` included).
- **Both actors are compared.** `github.actor` survives a re-run, so a person re-running a forged dispatch no longer skips the refusal or the proof; the proof step runs whenever either actor is a bot.
- **A bot re-run is refused** on every secret-holding job and on the three senders, for every event. A person's re-run still works, and the receiver proves a re-run's intent again when a person started it.
- **workflow_run listeners name the exact sender file**, its events and this repository; `publish-club-arena` listeners also prove every selected revision is an ancestor of `refs/heads/main` (`scripts/ci/selected-revision-is-on-main.sh`, fetched from the default branch) before checkout, install or scripts. `production-e2e-provenance.mjs publisher-run` checks the source run's path and event.
- **Tags never shadow branches.** Tag ruleset `tags never shadow branches` (27072304) refuses creating, updating or deleting `main`, `main/**`, `HEAD`, `refs/**`, `heads/**` and `gh-readonly-queue/**` tags. The repository had no tags.
- **The GitHub App key leaves ci-main.** Jobs that mint an App token name the main-only `github-app-main` environment; `move-github-app-key.yml` copies the key (and the three database values those jobs read) and, after a real Estate Integrity run succeeds on the new copy, deletes it from ci-main.
- **pr-engine-doors** runs only for same-repository pull requests, prints pull-request names and paths through a plain-alphabet filter, and installs the lockfile's exact `pg`.
