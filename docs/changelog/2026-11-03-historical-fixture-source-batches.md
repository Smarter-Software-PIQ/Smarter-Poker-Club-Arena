# Hydrate exact historical fixture sources before behavioral qualification

Repeated hosted qualification failed inside unchanged historical Git reads: the withdrawal fixture exhausted its 60-second boundary and the terminal-owner fixture exhausted its 30-second boundary after different completed cases while blobless checkouts left historical source blobs demand-fetched separately. These logs establish the timed-out source-reading boundary; they do not identify every elapsed subcommand or prove a provider outage.

Both existing fixtures now prepare only their finite pinned source closure in one configured promisor fetch, preserving immutable revisions, all source hashes, ancestry checks and behavioral assertions. Once hydrated, missing source refuses with lazy fetching disabled. Explicit wrapper preparation has a 90-second transport cap, reserves cleanup time, terminates its own Git process group and never updates tracking refs or FETCH_HEAD. The behavioral fixture only verifies already-present objects under a ten-second read cap; it cannot fetch. No production implementation, workflow, credentials or release authority changes.

A maintained real local promisor regression compares two separate original demand fetches with one batched fetch, verifies exact bytes and unchanged refs, and leaves an unrequested blob absent. Unknown references, an unconfigured promisor, failed transport and a delayed helper retaining pipes refuse without fallback; the delayed child is verified gone. All 64 original withdrawal cases and all 50 original terminal-owner cases remain; one added promisor regression brings the withdrawal count to 65. The existing platform-specific skip remains visible. Both wrappers read the shared helper path so a future helper-only edit selects their real behavioral checks. Hosted qualification of the final containing candidate remains required.
