# The original hand writer recognizes the installed lane rollback code

`server/src/services/supabase/handHistory.ts` previously retried canonical atomic rollback envelopes only for `40001` and `40P01`. The installed F06 lane uses `55P03` to avoid PostgREST internally replaying a custom serialization refusal. A temporary lane refusal therefore immediately reached `authoritative_hand_commit_not_proved` and stopped the table.

The original writer now accepts `55P03` under the same exact table, hand, rollback and commit-hash checks. It retains the existing two waits (250 and 1000 milliseconds), reasserts the original lease before dispatch, and reuses the same immutable retained request. Exhaustion still refuses; permanent errors, malformed receipts and unknown acknowledgements are not reclassified as a proved rollback. No new timer loop, successor claim, repair job, financial formula or migration is added. This repairs the caller/database contract, not the independent causes of long accounting or migration transactions.

Verification: the real postHandTasks/logHandHistory regression failed before for `55P03` while `40001` and `40P01` passed. Afterward all 107 focused tests passed, including two-wait exhaustion, identity mismatches, permanent refusal and lease loss before retry. The maintained PostgreSQL 17 hand-submission route passes 54 assertions and its existing concurrent ownership/disposition cases. Its new test induces an actual canonical `55P03` rollback, proves no financial commit and an unchanged retained request, commits with the original owner after contention clears, then proves replay creates exactly one conserved commit without a successor claim. The fixture uses captured authoritative owners; it is not a hosted PostgREST or production gameplay test. Native cluster stopped and removed. TypeScript and required source gates are recorded in the owning checkpoint before submission. Engine publication and live behavior remain separately required.

The accepted-roster qualification also executes this shared hand-submission probe before and after its migration. Its expected count is updated from 50 to 54 for the four added rollback/identity/conservation assertions. Required CI caught that stale consumer count; the complete accepted-roster native qualification now passes all 56 roster assertions plus both 54-assertion shared-probe executions and its installation, legacy-receipt and Lightning cases. Assertions and transaction behavior are unchanged.
