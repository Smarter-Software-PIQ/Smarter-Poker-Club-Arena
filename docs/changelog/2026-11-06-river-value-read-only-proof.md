# Bounded river value observation through the existing inspector

The existing manual Inspect Tournament Refill workflow now accepts version 8 `river_value` selectors through `reference_cases_json`. It retains the pinned SSH transport, exact serving-source/container checks, at-most-six original hand selectors and existing accepted journal reconciliation. No engine code, release dispatch or poker action is executed by this diagnostic.

Only original single-board high-only PLO4/5/6 checked-to river full-house contexts qualify. The observation distinguishes an actual prior aggressor who checked from a pending aggressor with installed non-bottom eligibility. The latter remains unavailable when the installed source lacks the eligibility helper. Both accepted bets and checks can be observed; a check is not silently discarded to manufacture a successful result.

The closed output contains source and record digests, selected/accepted action names, eligibility classification and bounded reference/candidate receipt comparisons. No cards, raw journals or opponent identities are emitted. Missing authority receipts do not establish baseline attribution. Every result explicitly denies causal replay, GTO certification and activation authority.

Validation covers original journal joins, source/acceptance failures, unsupported contexts, metadata/output bounds, private-field refusal and the actual host adapter path. Existing inspector modes retain their tests and original limits. The separate fixed river helper has a 16 KiB source bound; the existing predicate helper retains its 64 KiB bound.

This is a diagnostic capability, not proof that either initiative correction is deployed or that a qualifying natural hand has occurred. Deployment identity and an authenticated post-deployment observation remain separate required evidence.
