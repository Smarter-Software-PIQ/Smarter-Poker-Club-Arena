# Tonight's freeze baseline never yields to an owner window

After the nightly freeze every push-triggered Backup run certifies the freeze baseline (tonight's 04:00 build), not its own commit. The late owner-window check added by #11569 asked the priority tool about that baseline, which always predates a booking made later in the night, so it handed the host back: runs 44878744044 (the 0825z booking's own run) and 44884252356 both ended DEFERRED and the 04:00 build had no certificate at 02:53 Chicago. The custodian dispatched run 44887083680 (workflow_dispatch, not subject to the check) to certify f94c25f0 on the post-freeze copy. The plan step now emits `freeze_baseline=1` on that path and the late check never runs for it. Pinned in `tests/the-backup-day-ends-with-only-a-four-am-release.law.test.ts`.
