# Paced PLO startup opens its feeder

The funded production witness reached six players gradually but could not grow
beyond Main1. The shared controller required a separate two-buyer fleet forecast
before opening a destination; that forecast was one. Its randomized table cap
could also restrict the six-seat game to one table, making ON10 unreachable.

Migration20261110001650 patches the existing controller for the exact enabled
1/2 PLO4 six-seat game with ON10 and always-on disabled. It retains capacity for
two tables and permits the original OPEN decision at six through nine funded,
ready participants including a human. Full-floor, existing-opening, abandonment
cooldown, row serialization and maintenance safeguards remain. It does not seat
or fund anyone: real candidate eligibility, the no-lone-seat guard and durable
individual admission deadlines still govern arrivals. Other games retain the
two-buyer requirement. This scoped startup capacity implements the owner's later
ten-player and gradual 5–15 minute requirement.

The maintained Phase6 PostgreSQL route now loads the actual installed controller,
reproduces both original stalls, then proves picked/unpicked capacity, duplicate
and concurrent calls, negative controls and unchanged funded stacks. The pool
composition uses the actual opener and two-player promotion before ten-player
conversion, settlement, human exit and further Horse-only settlement. It no
longer creates the feeder itself. Exact postimage and function metadata checks
protect installation and replay. Only the picker clock is adapted in isolation.

This is ordinary protected-main SQL installation, compatible with the existing
controller RPC; it needs no engine replacement. Installation remains subject to
the active release operator's concrete schema hold. Qualification, installation
and the still-required fresh live startup/departure witness are recorded
separately in CHECKPOINT-plo-lightning-lifecycle.md.
