# Existing Apport raw-core metadata

The live Apport handler digest and package version match the independently verified official 2.28.1-0ubuntu3.8 source. That source can retain unpackaged Node raw cores under `/var/lib/apport/coredump` without creating `/var/crash` reports. Report absence therefore did not exhaust the existing artifact route.

The existing four-second restart container read now conditionally inspects only that fixed store after the exact verified handler digest and package-version checks pass. Root-owned, non-writable directory ancestry is opened without following symlinks. One iterator reads at most 128 entries plus a single overflow sentinel. Only the two Node UID-zero filename families with the current fixed boot identity can receive no-follow metadata checks. Candidates must be root-owned regular files with no group/world permissions. At most five candidate rows expose kind, bounded size, modification time and relation to the requested incident window; raw names, host PIDs, start ticks and boot identity never leave the reader. No core is opened, read, hashed, decompressed, collected or modified.

Truncation, excessive candidates, inaccessible or changed directories, untrusted files and unknown protocol identity remain explicit unknown outcomes rather than absence. Candidate metadata never proves incident or container attribution, which remains unproven. The existing four-second source budget, two one-second Docker identity reads and half-second package query remain unchanged. No producer, watcher, runtime change, host write or capture integration is introduced.

The focused actual-command regression covers both Node families, current-boot filtering, unrelated names, symlink/owner/permission refusal, exact 128-entry completion, truncation and candidate overflow, identity-preserving metadata and closed private exports. This only locates potentially retained evidence; it does not diagnose or fix a native crash. Protected delivery and scoped live read remain separate requirements.
