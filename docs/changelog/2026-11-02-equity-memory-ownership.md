# Bounded equity requests and worker memory ownership

An equity worker error previously removed the worker from capacity accounting before its asynchronous termination completed. Replacement workers could therefore overlap the memory of retiring workers. Retirement now retains capacity until termination completes, shutdown joins every owned termination, and the singleton cannot be replaced while shutdown is incomplete. Failed termination remains an explicit failure. The bounded routing grace period uses a monotonic clock, so wall-clock corrections cannot extend or prematurely exhaust it.

The request queue now has independent count and serialized-payload byte ceilings. Requests retain bounded copies of calculator fields, rather than arbitrary caller-owned graphs. Insurance can displace queued cosmetic requests, but never active computations or admitted insurance. Existing caller deadlines and fail-closed hand continuation remain intact. Queue bytes are released on dispatch, expiry, rejection and shutdown.

The existing health response and metrics expose actual main-isolate heap limits and available/constrained memory. Existing equity READY/result messages carry worker-authored isolate samples. Unknown measurements remain unknown. A backward wall-clock correction invalidates the cached sample instead of preserving a future-dated observation until the clock catches up. These observations neither traverse heaps nor trigger collection, repairs or restarts.

Regression coverage includes deferred/failed termination, singleton shutdown ownership, queue count and byte pressure, insurance priority, sparse/oversized inputs, detached request data, and a real bundled worker with independently known outcomes. `node server/scripts/qualify-equity-memory.mjs 120` runs a finite isolated mixed calculator qualification and reports samples; it is not whole-engine or production capacity certification.

This change alone does not establish a host resize requirement, remove the V8 main heap ceiling, prove long-term memory stability, or complete the nine-phase reliability programme. Protected delivery and actual engine adoption must be verified separately.

The Horse client also now requires available ownership before submitting an issued plan's effect commit. Previously a second call while the first was pending submitted another request; worker idempotency did not bound the duplicate client queue. The regression reproduces two posts before the correction and one afterward, while preserving unknown-outcome retirement rather than replaying the accepted operation. Confirmed duplicates reuse the actual prior worker acknowledgment, bound to the exact batch and accepted wager; altered or still-unknown requests cannot reuse it or post again. The real controller composition retains its accepted-wager/idempotency assertions. Its snapshot fixture now excludes the internal Deck instance, matching the production Turns adapter's public-state projection rather than relaxing the plain-data allowance.

Horse admission now bounds both unposted and posted request retention: 2,048 ordinary jobs, a conservative 2 MiB allowance per request, and 96 MiB per client including effect reservations. The maximum eight clients therefore admit at most 768 MiB of these allowances; these are not RSS measurements or process heap limits. Bounded traversal precedes queue retention, and queued data is detached from its caller. Status includes reserved bytes, outstanding plans and refusals at client, shard and fleet levels.

Each FAST admission reserves two 256 KiB control slots before it can issue a plan, with the same 128-plan ceiling as the worker. The largest sixteen valid outlook effects alone require 179,534 bytes under the conservative allowance, so the earlier 128 KiB proposal failed the boundary fixture and was increased. Ordinary backlog cannot consume these reserved slots. Caller timeout keeps posted requests owned until an actual reply; an unknown commit retains its reservation through the original retirement acknowledgement. Remaining reservations clear only after physical worker termination. This preserves effect ordering and adds no replay, timer, cleanup loop or policy change.

The reproduced 4,096-request burst now admits 2,048 requests instead of all 4,096. Its immediate heap delta is not a memory-plateau result: the fixture also retains rejected promises and copies until its cleanup. General request, mutation, oversized/accessor/cyclic payload, maximum effect, late-ACK, replay and real worker tests qualify the affected paths; full-engine sustained-load and deployed behavior remain separate acceptance requirements.

The existing hosted resource check now runs the maintained real-worker calculator for twenty minutes on Linux and retains its samples in the same artifact. The script preserves its report before refusing any dropped calculation, records main-isolate/external memory, and explicitly does not infer a memory plateau from successful execution. The thirty-minute Mac run completed 141,974 calculations without timeout but RSS reached 775MiB with later growth, so whole-engine capacity and the remaining growth attribution stay open.
