# Equal-share settlement uses operation-bound canonical readback

The equal-share controller called the postgres-only cancellation receipt helper after settlement. Production's actual service_role lacks EXECUTE, so a legitimate settled target would become unknown during readback. Stop-state's stored receipt alone does not revalidate economic evidence and cannot replace the canonical reader.

The reserved ordinary migration adds a service-only, operation-bound read-only equal-share receipt API. It requires an owned settled target and delegates to the unchanged private canonical reader, preserving its terminal snapshot, roster, allocation and credit validation. The returned v4 equal-share receipt must exactly match the owned stored receipt. No arbitrary actor parameter, private grant, payment, replay or table schema change is added. Exact canonical/private helper definitions and private execution boundaries guard installation.

Only the equal-share controller route changes, passing both original operation and tournament IDs. Existing full canonical/financial/tuple and unknown-outcome checks remain.
