# Legacy Data reports use Pacific calendar days

Standalone and pre-union Data reports previously read Chicago midnight buckets even after union accounting reports moved to Pacific midnight. The report-only Pacific projection now observes the original event writer's recorded club, player, game and timestamp. It retains original UTC/Chicago projections and money, fee rounding and commission settlement rules. Aggregate owners use a bounded try-lock; concurrent writers append private deltas instead of waiting on report rows.

A finite history branch of the existing Club Data loader reconstructs one UTC source day per repeatable snapshot, compares every original key's totals and club hand controls, then subtracts that snapshot's live capture. It does not redate aggregates by last activity, use current membership, clip mismatched amounts or infer an unnamed tournament roster. Original per-source attribution receipts must support unnamed tournament fees. Missing or ambiguous evidence remains a durable explicit failure. A selected incomplete window raises `CLUB_DATA_PACIFIC_WINDOW_INCOMPLETE`; partial figures cannot appear as a true zero. Optional comparison windows have separate coverage and no fabricated deltas.

Thirteen existing legacy Data doors now route through private Pacific copies. Separate Pacific Rake Snapshot/export APIs preserve the existing Chicago APIs used elsewhere. The by-agent production remains gross cash rake, separate from personal net earned fees, standing shares, redemptions and tournament credits. Its sealed/unsealed UTC cash cores and partial-day attribution edges retain original cents and hands. UTC whole-day commission cores and timestamp edge contracts remain unchanged; the report supplies Pacific boundary instants. Frozen exports include their Pacific basis and separate request identity, preventing a reused request UUID from resuming a Chicago question.
