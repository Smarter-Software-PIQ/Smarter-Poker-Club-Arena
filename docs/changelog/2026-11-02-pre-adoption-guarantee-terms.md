# Guarantees created before engine adoption

The old engine continued creating original guarantees while the permanent TournamentGuaranteePolicy awaited deployment. The finite migration captures 48 exact unentered November 5-7 instances: 37 derive from the original captured schedule amounts and 11 from the protected weekly schedule configuration. Each original amount is halved once, with resulting 1,200/1,250 raised to 1,500.

The nightly 35-entry 10K, Sunday 200-entry 25K, Six-Card 500, already reduced guarantees, and later Free Buy zero-guarantee conversions are unchanged. Union Late Night Turbo instance 011c5cd2-74af-4747-b67e-3497b8a3c0ff stays at 1,000: the owner's final 137-instance leave-everything-else baseline explicitly preserved that amount.

The migration requires exact tournament/schedule IDs and original amounts, an unentered registering event, an unlocked entry contract and an unfinalized pool. It changes no wallet, payout, participation, table or schedule. Existing native PostgreSQL qualification exercises every captured row, accurate labels, repeat safety, every commitment guard independently, and unchanged unrelated rows. Installation and actual creator adoption remain separate required proofs.

The previous required Accounting shard 6 failed before its financial assertions because four fixture clubs used the captured random five-digit short-ID default and collided on 69055. Those four inserts now supply stable fixture-only IDs outside that random range, and the existing native regression pins them. No production default, uniqueness constraint, financial logic or assertion is removed. The source binding records the exact changed fixture bytes.
