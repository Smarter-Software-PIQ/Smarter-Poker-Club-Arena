# Cancellation retains native process-group bindings

The live-process cancellation profile saved its original release group but did
not save the intake service's group. After instance masks and daemon-reload,
the intake path's native empty proof could reach an unloaded companion whose
current `Slice` no longer described its original template. Continuation
41916032088 refused at that predicate before issuing any stop or deleting
original custody. The diagnostic did not export the actual Slice value.

Every new live-profile intent now captures both native canonical service
groups before masking. Existing immutable owner-window intents can recover
those bindings only from their original release group, byte-exact templates
rendered from the protected original installers, absence of applicable
drop-ins, unchanged request/runtime evidence, and positive native process and
cgroup emptiness. Loaded failed units use the existing typed process
enumeration; unloaded units use typed manager absence and the canonical group.
Mask-default slice metadata never supplies the original binding. Intent bytes
remain unchanged, and terminal receipts retain the bindings for safe replay.
Recovery also persists a create-once companion binding record tied to the
original intent hash before terminal unlink, so interrupted cleanup can resume
without reconstructing already-retired request files.

The connected regression fails on the prior source at the same Slice
predicate. Qualification covers masked/unloaded cleanup and receipt replay,
mixed loaded/unloaded units, foreign templates, drop-ins, groups, slices,
control processes, manager identities and populated groups. Existing one-stop
and lost-response tests remain enforced. The Linux systemd fixture also
captures live bindings before masking and proves emptiness afterward. Local
macOS qualification does not substitute for that required hosted native case
or production cancellation/live-engine verification.
