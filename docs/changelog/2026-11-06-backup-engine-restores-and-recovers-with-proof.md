# Backup Engine Restores And Recovers With Proof

The isolated Backup Engine's restore reported seven errors: duplicate public schema creation, absent pg_cron relations required by two views and their metadata, and an absent ca_record_gateway ACL role. The maintained restore now installs the real empty pg_cron extension, creates the missing NOLOGIN role, and omits only the duplicate public-schema CREATE from the archive TOC. Other objects and grants remain intact. Every restore, owner alignment, trigger installation and seed failure prevents a valid copy receipt and certification; refresh failure replaces any prior success status for the same SHA with failure.

The standby container now uses Docker's unless-stopped policy. Certification terminates PID1 and proves automatic recovery of the same container and exact engine SHA, with an increased restart count. Any further restart during soak fails certification. Table-kill trials compare their own restart baseline. Certificate evidence records the actual standby script hash separately from the candidate engine SHA.

Focused regressions exercise the actual shell failure propagation, invalid/stale restore and seed receipts, conditional-caller behavior, and recovery identity/count boundaries through the existing DR posture test. Real PostgreSQL restore and Docker crash/soak qualification remain required on the isolated backup host after protected merge. This change does not turn the backup into automatic production failover and does not authorize a production restart.

The existing seed also failed six tables. Four failures were historical rows grandfathered by production NOT VALID checks; the archive's exact post-data CHECK entries now install after loading those rows. Validated checks and all other schema objects retain their original definitions. The standby is explicitly stopped and verified stopped before schema replacement, preventing its leader and telemetry writers from racing the seed. Clubs load before memberships because the real automation CHECK reads club properties.

The existing horse-only fixture included nonplayable memberships from a retired club. The extractor now records identity pairs, count and reason for excluding only CHECK-invalid memberships proved retired, nonactive, unfunded and without playable tables or live seats. Any invalid membership lacking those proofs aborts extraction. No production row or constraint is changed.

Seed and placeholder loading now capture each affected trigger's original O/D/R/A mode, including descendant tables, and restore that exact mode within the same transaction. A failed load rolls back both row changes and temporary trigger suspension. The previous ENABLE TRIGGER ALL/USER converted every affected mode to ordinary enabled. Read-only comparison found the backup clubs and table_seats replica-money guards in O mode while production retained A. Placeholder insertion is now transactional as a whole; internal FK trigger behavior remains unchanged.

Disposable PostgreSQL 17.11 qualification reproduced original-source loss of A/D/R on the parent and partition child. The corrected source preserved all four modes for successful loads and failed-load rollback, including full placeholder auth/profile rollback and unchanged internal FK trigger modes.
