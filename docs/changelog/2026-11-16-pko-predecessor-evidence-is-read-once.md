# PKO predecessor evidence is read in one bounded query

Incident `610bf7b7-59c5-4dd5-991c-dd3bfee72372` exposed the remaining SQL ceiling in the serial PKO bust path after #10833 reduced its network trips. For each claim and payment, `fn_pko_claim_predecessor_status_v1` called the accepted-scope validator for every historical candidate, then reread unrelated hand histories for contradictory recipient evidence. A read-only production call inspected 1,255 candidates for 18 relevant heads in 864.92 ms. The original backlog later drained naturally; that recovery does not remove the growing historical-read cost.

The private stable joined reader loads the same bounded candidate set and its atomic, settlement and history evidence in one query. It validates every written stack, the entire ordered roster, accepted identities and clocks, and contradictory recipient narrative. Identical roster stack text reuses the already validated written-map domain; alternative numeric text still receives the original checks. The existing predecessor loop retains its causal, obligation, marker, unknown and 10,000-candidate overflow decisions. The target's original validator, public financial callers and payment rules are unchanged. No cache, new schedule, financial replay or manual player repair is introduced.

The maintained PostgreSQL gate compares the complete old/new JSON across 41 evidence cases and a nine-seat 1,255-candidate scene. The native scene measured 125.205 ms before and 83.112 ms after; timings are evidence, not a machine-dependent pass threshold. Earlier warm EXPLAIN measurements were 130.389/86.864 ms and 26,364/9,266 shared buffer hits. Full real financial-catalog callers retain rollback checks and actual concurrent commit/rollback lock races. Installation tests require unchanged business data, exact replay, three private-role refusals and body/ACL drift refusal for all three affected helpers. Guarded migration installation and natural production proof remain separate delivery requirements.
