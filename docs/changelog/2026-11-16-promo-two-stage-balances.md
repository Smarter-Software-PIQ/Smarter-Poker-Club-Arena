# Promo Balances And Two Fee Targets

Wallet, cashout and member displays call the chip total Balance. Withdrawable Balance appears only when the authoritative player-wallet promo principal or restricted promo profit is positive. Table/event principal and a source review hold alone cannot create that second wallet balance. The roster keeps it inside the existing financial permission and wallet-column boundaries.

The existing promo figure and inline row consume the optional source-attributed profit fields: the 2× profit fee progress disappears once the actual restriction is gone, while the 4× original-principal progress stays independent. Both use the same qualifying fees. A rounded 100% cannot hide an unfinished restriction. Missing wallet-specific fields never infer a second balance from aggregate table or event custody; programme activation requires the actual wallet and profit source contract.

The actual pre-play agreement, published terms and player/agent promo senders now share the 2× profits / 4× principal rule, overlapping fee targets, exempt own cash/deposits/rakeback, permanent complete loss and nonexpiring restricted profit wording. Source review remains separate. This client change does not alter the backend cashout ceiling or create a new fee target.

Focused render/parser/roster/stale-response tests, the app typecheck, legal rendered-word fingerprints and the existing copy gates qualify the client. A 393px local render loads both real fonts and has no horizontal overflow. Production publication and the new profit backend remain separately verified prerequisites.

`agent_cashable` fields, and appears only while that actual agent wallet has
restricted P or W. Missing/non-agent fields stay nullable; a player wallet is
never substituted. Source review alone leaves the second balance hidden.

transition. Its one-per-gift receipt keeps principal amount zero, records actual
W holdings separately and cannot enter the original-principal digest total.

earned completion. Actual transition/outbox, stale recipient refresh and agent
balance regressions are retained; full W financial allocation is a separate proof.

The original P override and the W override receipt share one non-earned support
update notice per gift. It refreshes the recipient through the existing channel
without a wallet balance change, private review note, earned-fee claim or H release.
