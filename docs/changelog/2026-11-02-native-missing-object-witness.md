# Identify absent native objects without publishing private schema

The sixteenth connected capture refused exact service composition at
`NATIVE_OBJECT_MISSING`, before executing any of the fifteen product cases.
The former diagnostic identified the refusal site but did not identify which
native object key was absent from the captured schema.

The same private Error identity and descriptor checks now expose a separate
missing-object witness for that exact refusal. It contains only the native
ordinal, SHA-256 of the existing object key, and closed object-type/schema tags.
There are at most sixteen rows within the existing sixteen-KiB diagnostic file
bound, with a total count and explicit truncation. Unknown types and schemas
become `OTHER`. No raw name, SQL, owner, or invented captured counterpart is
included. The Python consumer independently validates the closed shape, bounds,
unique keys, native ordering and exact phase/site, and refuses cross-site or
mixed witness payloads.

Exact key, owner and raw block comparison remain unchanged. Existing block
mismatch witnesses remain separate and unchanged. This diagnostic does not fix
the absent object, qualify full schema composition, or prove product behavior.

Focused validation: the new JS cases fail against the previous source because
the missing-object accessor does not exist; after implementation, all forty-four
schema-snapshot tests pass with no skips. All fourteen connected native Python
tests pass, including the actual Node command and decoder. Negative cases cover
forged and mutated Errors, getters/proxies, raw counterpart/name/SQL fields,
wrong site/phase, boolean integers, excessive bounds, duplicate keys, reordered
ordinals and truncation disagreement. No production writes or capture retries
were performed for this change.
