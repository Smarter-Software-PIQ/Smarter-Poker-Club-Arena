# Additional five old events retain their original refund owner

The November 3 closeout manifest adds five chip events outside the original 140-event retirement disposition. Physical `owner_request`/`owner_ack` already admits them, but legacy `abort_settle` admits only the original other69 cohort. The additional events therefore had no maintained operator execution route to their existing original-charge refund authority.

`additional_refund_read` and `additional_refund_settle` now accept exactly the additional-five manifest, retain each original operation UUID, and reuse the existing canonical abort readback and `fn_ca_settle_tournament_abort` payer. Settlement requires current serving identity, generation, valid drained boundary and independently reviewed money hash. A lost acknowledgment stays unknown and reads the same durable outcome without retry. Already settled operations do not repay. Original140 retirement, its bank transfers, legacy controls and physical stop authority remain unchanged.

Two classifier cases ensure the adapter/helper select required accounting and source tests. Every case verifies rollback equality, exact recipient wallet restoration, zero closed escrow, canonical terminal receipt and unchanged replay. The added cases run once under the existing hand-continuation accounting owner.
