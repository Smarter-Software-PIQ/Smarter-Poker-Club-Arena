# 2026-11-28 - two #SmarterDesign lanes can never conflict on its docs again

## What was wrong

The #SmarterDesign sweep kept two shared, committed documents that every lane
edited:

- `docs/club-operations/SMARTERDESIGN-INVENTORY.md`, generated by
  `node scripts/smarterdesign-inventory.mjs --write`, with a law requiring the
  committed file to equal the scanner's output. Every page conversion rewrote it.
- `docs/club-operations/SMARTERDESIGN-HISTORY.md`, append-only, every batch
  adding a section to its end.

So every merge to main made every other open #SmarterDesign lane conflict on
both files, and each resolution cost a full (about 30 minute) CI rerun. Merges
were serialised behind a document nothing executes, and a local helper script
(`resolve-sd-docs.sh`) existed only to re-resolve the same conflict over and over.

## What changed

**The inventory is printed, not committed.** `node scripts/smarterdesign-inventory.mjs`
prints the summary and to-do list as before; `--write [path]` writes the full
document to the gitignored `.smarterdesign/inventory.md` (and to
`$GITHUB_STEP_SUMMARY` when set). The generator and every classification are
unchanged.

**What is committed is a ratchet, one file per converted page:**
`docs/club-operations/smarterdesign.d/<Component>`, one line holding the page
module path. 58 entries at the time of writing, written by the new
`--ratchet` mode (which only adds). Two lanes converting two pages add two
different files, so they cannot conflict. The law
`tests/the-smarterdesign-inventory-matches-the-code.law.test.ts` now fails when:

- an entry no longer reads as converted (the page lost its arena root or mast,
  or gained a painted section) - named, with the scanner's reason;
- a converted page has no entry (run `--ratchet`);
- an entry present on the base branch (`CI_BASE_SHA`, else the merge base with
  `origin/main`) is removed while its page is still routed and graded, so a
  downgrade can never be hidden by deleting its entry; an unreadable base is
  UNKNOWN and fails, never a pass;
- either retired shared document comes back.

The scanner sanity checks (enough routes read, the reference pages read as
converted, the skin is never a conversion, every exclusion names a page) are
kept unchanged. `--claims` now also counts a PR that adds a page's ratchet entry
as a claim on that page.

**The history is one file per batch:**
`docs/club-operations/smarterdesign-history.d/YYYY-MM-DD-<batch>.md`, the rule
`docs/changelog/README.md` already applies. The old file was split section for
section into nineteen dated files and removed. `node scripts/smarterdesign-history.mjs`
prints the whole history in order; `--rescue <batch>` moves a lane's own added
lines out of the retired file during its last conflicting merge. The new law
`tests/the-smarterdesign-history-is-one-file-per-batch.law.test.ts` holds the
names (real date, lowercase slug), the level-two heading, no conflict markers,
the print order, and the retired file staying gone.

Both laws literally name their directories, so the ungated docs-reader step
(`scripts/ci/run-docs-readers.mjs`) runs them on a docs-only pull request; each
law asserts that it is selected.

The smarter-design skill (section 5.5 and the definition of done) now tells
lanes to add a ratchet entry and a history file, never to edit a shared
document, and carries the one-time recipe for the last conflict.

## For lanes open before this merged

Their next `git merge origin/main` stops once on the two deleted files. The
recipe is in `.claude/skills/smarter-design/SKILL.md`, "The last conflict on the
retired files": `node scripts/smarterdesign-history.mjs --rescue <batch>`,
`git rm docs/club-operations/SMARTERDESIGN-INVENTORY.md`,
`node scripts/smarterdesign-inventory.mjs --ratchet`, add both directories, run
the two laws, commit. `resolve-sd-docs.sh` is retired.
