# Focused published hero celebration proof

The celebration check no longer waits behind the unrelated cosmetics journey.
A separate bounded case reuses its real disposable account and local-only hand
projection to check the published client for loss, small chop and sole win.
Both public build identities bracket the case; guarded account cleanup is required.

The existing Post-Deploy E2E workflow accepts the explicit
`run-hero-celebration-proof` event with a full protected `client_sha`. Its focused
configuration runs just this case, with no shared authentication setup or retry.
The ordinary cosmetics case and existing verification jobs retain their checks.
No production gameplay, engine or payout source changes in this follow-up.
