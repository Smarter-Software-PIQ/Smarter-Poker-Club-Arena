# Captured provider configuration

The isolated qualification fixture lacked retained object grants on genuine
PostgreSQL extension members and cron tables, and the Realtime messages
publication member. Capture21 therefore stopped before full-schema restore and
the fifteen application cases.

The original private Admin bootstrap now applies three guarded configuration
modules in its existing transaction after all thirteen genuine providers. Each
requires its exact native preimage, uses ordinary PostgreSQL operations and
verifies its captured postimage through a fresh observer. Genuine definitions,
initial privileges, provider membership, PUBLIC grants and creator defaults
remain unchanged. Any drift or failed operation refuses with rollback. No
production database or engine change is included.

Private PostgreSQL native proofs and focused regression checks accompany the
source. Required hosted native qualification, protected merge, publication and
full-schema/connected application verification remain separate delivery gates.
