# Backup seat proof admits the candidate owner

Swap run 42309099728 retained identical seats and freeze boundaries but failed because its proof required the predecessor token after boot. The actual engine deliberately rotates that token: `MaintenanceBreak.claimPersistedState` calls `fn_claim_engine_maintenance_break`, which compares the old token atomically, changes ownership and `declared_by`, and preserves the break semantics. The new token prevents the retiring process from clearing its successor's freeze. The previous native fixture omitted this real adoption step.

The trial now admits exactly one candidate transfer during its controlled replacement. The container label and health must match the full candidate SHA, health's database version must match its first eight characters, and the same container, health instance ID and Docker restart count must remain present across capture with live or standby health. The admitted runtime identity is retained in the verdict. The adopted snapshot must carry that declared version, a changed token, identical phase, announcement, reason, freeze/release times, seat count and identities. Every subsequent frozen sample remains pinned to this successor. Its v3 receipt must match the announcement, token and boundaries, and both thawed-by and maintenance-log versions must match the candidate. Original, adopted and last verified snapshots remain in the verdict. Unobserved durations render JSON null rather than subtracting a missing timestamp from an epoch.

The existing DR suite exercises legitimate adoption, arbitrary owners, changed semantics/seats, repeated rotation, incorrect container/health identity and unknown durations. Disposable PostgreSQL 17 qualification executes the actual current claim function: the old proof rejects its legitimate rotation, the corrected proof accepts it, and stale expected tokens, unrelated owners, later rotations, semantic/seat mutation and wrong receipt versions fail. The native fixture substitutes only the surrounding maintenance-admission dependency and freeze predicate; it does not qualify production admission. The current database stores no immutable predecessor-to-successor archive, so this proof is bounded to the controlled replacement and observed candidate, not an invented retrospective lineage record. No production or backup host was mutated during source verification.
