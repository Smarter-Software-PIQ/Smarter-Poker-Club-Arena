# Original tournament outcomes survive lost transport

The existing PostgreSQL accounting qualification now runs the actual TypeScript terminal client against independently rebuilt PostgreSQL 17 financial owners for MTT, SNG and Spin. Each format covers a committed response lost over TCP, a resolver waiting for the original transaction to commit, the same transaction rolling back, and an unresolved original operation whose resolver response is also lost.

The resolver must demonstrably wait on the original database transaction. Committed outcomes retain the exact immutable receipt, and replay must preserve every row in the public and private fixture tables. Rollback leaves the opening unchanged; an MVCC miss while the original transaction remains open stays unknown. A committed or refused answer must reach the caller within two seconds of releasing the original transaction. The tests record the actual measured durations.

Funding is real within each disposable database: three 100-chip zero-fee MTT entries, two one-chip zero-fee SNG seat purchases, and three one-chip Spin purchases with the original 0.24 fee, reserve contribution, lease-bound launch and randomized immutable draw. Expected Spin payouts come independently from that draw. No payout, funding entitlement, draw, launch or terminal receipt is seeded.

The maintained financial foundation is extended with a hash-pinned, read-only November 3 catalog capture of the exact missing source owners and schema dependencies. It contains definitions and permissions, not production player or financial rows. Local capital, control configuration, agreement terms and final roster/seat topology are synthetic. The original captured Stage B guard state remains disabled; this does not qualify Stage B activation. The local HTTP shim is not PostgREST, protocol-2 request fencing, a running tournament manager or an engine hand-completion proof. Final-table deals, production adoption and uninterrupted live play remain separate requirements.
