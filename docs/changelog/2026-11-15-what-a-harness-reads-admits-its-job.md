# What an accounting harness reads admits the accounting job (2026-11-15)

#10888 changed `scripts/verification-harness/cashier-release-contract.sql` and its fixture `scripts/ci/fixtures/world-hub-cashier-migrations-20261114.json`. Neither file is named in the `accounting_postgres` block of `ci.yml`, so the change admitted no CI job at all. `scripts/ci/test-promo-downline-limit-postgres.py` reads both files and is started by `scripts/ci/test-cashier-authority-exact-intent-postgres.py`. It was not run and broke on main (fixed forward by #10916).

The classifier already admitted the job for every file the block names. It now also admits it for every file a named harness reads:

- `scripts/ci/accounting-harness-reads.json` is generated by `node scripts/ci/accounting-harness-reads.mjs --write`. It holds every existing repository file that a named harness spells out as a literal, followed through the `scripts/ci|dev/test-*` harnesses one of them starts.
- `classify-ci-changes.mjs` reads that list. Every file on it, and the list itself, admit `server`, which gates the accounting job. Nothing else changes: unit-suite (`tests`) admission is unchanged.
- Three things are deliberately not read as inputs, because existing routing laws pin them out of this job: a directory (a harness that lists a whole fixture or probe tree would admit every neighbour), a routing law test (`*.law.test.ts` spells paths as routing data; `tests/ci-tells-the-truth-faster.law.test.ts` names the Diamond screenshot tools to keep them out), and a test file (qualification probes hash `tests/unit/fixtureNativeCi.test.ts` as data).
- `tests/unit/theAccountingJobNamesItsOwnInputs.test.ts` regenerates the list and fails when it differs. It runs wherever the unit suite runs, including the daily whole-branch run; a harness-only pull request does not run it, so a harness that starts reading a new file is caught there rather than in its own pull request. It also pins the #10888 files and the three exclusions.

Measured effect: besides the two #10888 files, 26 qualification-pinned files read by accounting harnesses did not admit the job before (union provider preimages, union P&L inventory, tournament accounting provenance, commission club history, original-flow eligibility, cash participant funding and two others). `scripts/qualification/ci-admission-inputs.json` changes in exactly those 26 cases, each `server` false to true. It was regenerated with `qualification-input-projections.py --write`, and the ten bindings that pin it were restamped with an audit entry `whatAHarnessReadsAdmitsItsJob20261115`. The full-weekly-accounting binding also restamps the three bindings it pins. `verify-source-bindings.py`: 1,856 pins, all match.

This only widens admission; no job that ran before is skipped. No financial input, assertion or qualification result changes.
