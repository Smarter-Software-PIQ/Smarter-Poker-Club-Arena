# What an accounting harness reads admits the accounting job (2026-11-15)

#10888 changed `scripts/verification-harness/cashier-release-contract.sql` and its fixture `scripts/ci/fixtures/world-hub-cashier-migrations-20261114.json`. Neither file is named in the `accounting_postgres` block of `ci.yml`, so the change admitted no CI job at all. `scripts/ci/test-promo-downline-limit-postgres.py` reads both files and is started by `scripts/ci/test-cashier-authority-exact-intent-postgres.py`. It was not run and broke on main (fixed forward by #10916).

The classifier already admitted the job for every file the block names. It now also admits it for every file a named harness reads:

- `scripts/ci/accounting-harness-reads.json` is generated by `node scripts/ci/accounting-harness-reads.mjs --write`. It holds every existing repository file or directory that a named harness spells out as a literal, followed through the `scripts/ci|dev/test-*` harnesses one of them starts.
- `classify-ci-changes.mjs` reads that list. Every file on it, every file under a directory on it, and the list itself admit `server`, which gates the accounting job. Every accounting input also admits the unit suite (`tests`).
- `tests/unit/theAccountingJobNamesItsOwnInputs.test.ts` regenerates the list and fails when it differs, so a harness that starts reading a new file cannot merge with it unlisted. It also pins the #10888 files.

Measured effect: besides the two #10888 files, 54 qualification-pinned files read by accounting harnesses did not admit the job before (fixtures for cash participant funding, late seat flow, union provider preimages, commission club history, original-flow eligibility and others). `scripts/qualification/ci-admission-inputs.json` changes in exactly those 54 cases, each `server` false to true. It was regenerated with `qualification-input-projections.py --write`, and the ten bindings that pin it were restamped with an audit entry `whatAHarnessReadsAdmitsItsJob20261115`. The full-weekly-accounting binding also restamps the three bindings it pins. `verify-source-bindings.py`: 1,856 pins, all match.

This only widens admission; no job that ran before is skipped. No financial input, assertion or qualification result changes.
