# Data Reconciliation Uses Original BBJ Sources

Invoice-backed Data and Rake answers now carry separate cash and tournament
reconciliation, original gross BBJ contributions, original stack awards and net
BBJ. The existing headline amounts and distinct game counts are unchanged.

The existing accounting aggregate and insert-only journal gain two reporting
columns. Cash contributions come from the finalized original rake attribution
matched by record and player, owned by the original accounting funding admission
when present. A missing original record and attribution cannot prove zero. The
existing admission callback moves both fee and BBJ ownership; the original award
reader supplies awards. Financial producers, commissions and personal net earned
fees are unchanged. No new trigger, schedule or repair process is introduced.

The existing finite accounting loader reconstructs these fields using its
original snapshot, bounded slices and live subtraction. Version-zero receipts
cannot certify BBJ. A pre-attachment source writer must finish first. During a
version-one multi-part reconstruction, owning accounting coverage reports the
day missing and the invoice headline doors refuse partial figures. The final
receipt restores availability atomically. Old unqualified BBJ is unavailable,
never a fabricated zero; existing posted headline amounts remain available until
an actual reconstruction starts.

Reader enrichment uses only the scoped accounting aggregate, respecting the
selected cash game IDs and downline users in the same statement as the headline.
Exports freeze the reconciliation and original accounting coverage before their
existing metadata fingerprint. Previously prepared immutable exports remain
their original receipts.

The rejected original-source polling query took 35.9 seconds for the audited
week's 2,114,996 participants. It is not shipped. Original participant evidence
is consulted once in the maintained finite loader and original source callbacks;
public refreshes read compact reporting rows.

Validation: the maintained private accounting PostgreSQL driver passed 67
top-level assertions plus retained SQL scenarios covering finalized attribution,
original ownership transfer and awards, unknown-source refusal, Pacific DST,
old-writer and in-progress rebuild refusal, nonblocking journal contention,
idempotent finite reconstruction, public Data totals and filters, downline scope
and private access. Four focused law/unit files passed 30 tests; app TypeScript
passed. Installation, finite production reconstruction and publication are owned
by the task's existing delivery owner.

## BBJ-Only Source Qualification

The original accepted-hand contract can charge BBJ independently of a positive
rake obligation. Such a hand has no finalized accounting cash rake source.
A sparse built-in GiST interval index now selects only original positive BBJ
obligations without a proven positive rake obligation. The existing maintained
concurrent-index preamble builds it before the migration transaction; the body
refuses an absent, INVALID or mismatched index before installing any field or
reader. No hot-table trigger, money writer or engine code changes.

The interval is only a candidate filter. Read-only qualification matches the
actual original acceptance date or exact BBJ bank receipt date, and the original
outcome or pool union. Delayed banking does not mask intermediate days or the
completion clock's next day. Other unions and explicitly standalone hands do
not affect this union. Genuinely unknown original scope is unavailable only on
its actual acceptance date. Missing or zero rake fields are never mistaken for
a proven positive original rake obligation.

An unsupported hand sets reconciliation source `bbj_original_source_gap`, marks
its dates missing and returns null BBJ figures. Existing posted fee/winnings
headlines and their original source/billing coverage remain unchanged. No
allocation is invented. Original sparse evidence survives any report rebuild,
so a version-one receipt cannot erase this qualification condition.

The changed maintained native driver passed 73 top-level assertions plus SQL
scenarios, retaining the previous 67. It exercised the actual concurrent
preamble, an INVALID build refusing the body, late banking across midnight,
scope and pending boundaries, and unchanged public headlines with unknown BBJ.
With 20,000 regular and 1,000 older sparse synthetic decoys, the normal planner
selected the GiST index and read two candidate rows in three shared-hit blocks
(0.059 ms warm private execution). This is index-shape evidence, not a production
latency guarantee. The existing four focused files passed 30 tests and the
maintained concurrent-preamble tests passed 21.

The first production concurrent index build reached its existing 600-second
budget before the migration transaction was sent. The qualified retry uses a
new index name and a timestamp-first CASE, so completed obligations before
November 9 do not detoast their historical JSON. Earlier accepted obligations
remain candidates if completion is later or pending. The reader uses the same
predicate and retains the exact original accepted-day/bank-receipt-day and
union checks. BBJ before November 9 stays unavailable even with a version-one
seed receipt; fee/winnings headlines retain their existing availability.
The original failed INVALID index is retained explicitly, without DROP or a
changed installer timeout. Native qualification retains that artifact beside
the new valid index and tests the floor, late bank receipts and pending spans.
