# Pacific Data cash follows original funded ownership

Legacy parent-table seat fallback could assign a child-funded player's cash fee to a different club. Pacific Data now resolves the original attribution, frozen cash source and funded admission in authority order while retaining the original unrounded contribution-weighted fee. Original UTC/Chicago writers and financial contracts remain intact.

Existing rake, attribution, cash-source and funded-admission callbacks observe the source atomically. Append-only authority receipts avoid shared receipt-row waits; later authority immediately suppresses earlier ownership. Cash source groups fold before game presence so an ownership correction cannot leave a phantom game. Tournament zero-fee entries remain visible.

Finite history checks cash amounts across original game/player keys; those controls prove conservation, never ownership. Positive-contributor Data hands are rebuilt from original rake IDs, rather than compared with the different UTC counter that includes zero-contribution clubs. A versioned seed receipt prevents an older basis from certifying new reads. Pending or unproved sources retain the existing explicit incomplete-window refusal.

Native PostgreSQL qualification retains the previous projection, access, fee, DST and source checks and exercises wrong unique ownership, raw fractions, signed game-presence correction, actual source hooks, original funded admissions, and concurrent duplicate observers.

The existing Pacific aggregate captures remain the baseline. Source observations carry only signed ownership corrections or a missing-capture fallback; same-owner receipts do not replay every raw fee into report reads. Original stage-zero club and distinct club-hand receipts preserve the source baseline through later funded admissions.

Append-only participant and whole-record completion witnesses qualify immutable source authority inside the original callbacks. Standard completed records use an indexed coverage anti-join. Concurrent split callbacks remain readable after commit through the unfinished-record participant fallback, without a repair callback, read-side write or recurring process. Later original-source ambiguity still appends visible failures for original, canonical and captured-baseline candidates.

Private performance qualification uses 100,000 current participant sources, 100,000 older decoys and 3% current funded-ownership corrections. It measures the real fact, hand, completeness and public reader paths with unforced PostgreSQL plans. This synthetic warm private environment does not guarantee production latency; the owning deployment records actual measurements and live verification separately.

Final warm private PostgreSQL measurements for that mixed fixture: fact totals 424 ms, completeness 124 ms, club hands 211 ms, and the actual public screen 900 ms in EXPLAIN ANALYZE (1,191 ms including a separate local call). Exact output was 200 games, 970.00 fee and 97,000 club hands after 3,000 source moves. The source-key conflict probes stayed indexed instead of hashing unrelated observation history. These measurements qualify the finite fixture, not production's full population or future latency.
