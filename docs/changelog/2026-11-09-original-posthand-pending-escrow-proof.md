# Original pending escrow completes its own accounting admission

The retained proof accepted only a single fully applied addon with a signed predecessor. Genuine rebuys, multiple participants, first occupancy and partial or fully refunded pending applications could therefore leave accepted cash basis incomplete after the original financial transaction had completed.

Extend the existing original proof seam to validate the complete sealed pending set, wallet owners/debits, original application frames, refund ledger multiset, seat-event continuity and exact played opening. Direct prehand wallet addons without pending IDs are proved from original debit/frame and the complete same-transaction seat-event chain rather than omitted from the opening balance. Preserve signed outcomes, monetary rows, existing immutable certificate bytes and all 68 qualified reporting readers. The original hand completion event now admits its own proven accounting certificate after every application completes. Expected reporting refusal remains visible in its completion result without rolling back otherwise valid financial completion; unexpected database errors remain errors.

A prerequisite concurrent table/time/key cover and a private generic-plan scalar lookup bound the predecessor read without changing its predicates or ordering. The owner migration requires the exact valid index before activation and guards source preimages, metadata, private access, postimages and unchanged proof generation. Historical certificate admission remains a separate finite existing-writer operation, with no payment replay.

Regression protection extends the existing native PostgreSQL17 escrow route with deterministic synthetic temporal, refund, first-admission, multiple-participant, replay, error and installer cases. The scratch-volume check follows the configured external SSD directly. Protected merge, recorded installation and actual Midway book/ECO closure remain distinct from local qualification.
