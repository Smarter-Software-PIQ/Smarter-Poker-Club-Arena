# Read the original terminal perf-install failure without retrying it

The first production installation produced a valid terminal failed receipt but the immutable original controller does not export its closed command failure or APT-attempt state. The existing receipt mode now validates that original receipt first, then reads only a terminal, same-invocation, empty-helper-cgroup operation through a protected static Python stdin adapter. The original installer controller, native identity controller and package plan are hash-pinned before their reader functions execute; the original profile and operation bindings remain authoritative.

Diagnostics contain only the closed original command outcome, phase, attempt presence and fixed public target/dependency package statuses and candidate versions. Global dpkg audit is a boolean. Package queries disable on-disk APT cache generation through command-local empty cache names, as specified by [APT configuration documentation](https://manpages.debian.org/trixie/apt/apt.conf.5.en.html). No install, retry, staging, state write, unit submission, engine action or raw command/log export is added. Failed installation exit semantics and retryAllowed=false remain unchanged; missing/malformed diagnostics stay unverified.

Portable tests cover exact bindings, privacy, malformed data, terminal admission and unchanged records. The existing isolated Ubuntu install qualification adds the exact stdin adapter after its already-required terminal install, proving original operation/APT-intent bytes and folder entries unchanged. It adds no install, expiry or native fault. Real Linux qualification, protected delivery and the original operation's production diagnostic read remain pending; this is not an installation or native-cause fix.
