# Fixed native pipe-handler artifact metadata

The live restart observation identifies a pipe core pattern while the existing systemd-coredump journal has no retained records. That does not exclude a report owned by a different handler. The existing four-second container metadata read now classifies only exact maintained Apport and systemd executable tokens. It exports no handler arguments and introduces no subprocess or timeout budget.

Only Apport permits metadata checks of the two fixed root-owned Node report candidates under `/var/crash`, corresponding to `/usr/local/bin/node` and `/usr/bin/node`. The maintained legacy native scale preflight explicitly selects `/usr/local/bin/node` from the pinned engine image. This is a candidate naming convention, not proof of the crashed executable. Directory opens refuse symlinks; candidate metadata does not follow symlinks. No report or core contents, environment, command arguments, directory enumeration or arbitrary paths are read. Exports are limited to candidate kind, availability, bounded size, modification time and relation to the incident window. Attribution remains unproven, and metadata describes only the read instant. Systemd artifact lookup remains unproven rather than guessing a historical PID or scanning its store. Existing exact-window coredump journal metadata is unchanged.

Focused regression covers the actual subprocess command, exact executable matching, two fixed candidate bounds, symlink and inaccessible-directory refusal, missing candidates, identity changes, closed exports and timestamp/number validation. This observation-only change does not enable capture, mutate production, collect raw cores, diagnose a native callsite or fix a crash. Protected delivery and one scoped live observation remain separate requirements.
