The existing bounded restart container observation now fingerprints only the fixed `/usr/share/apport/apport` handler when that exact executable token was classified. The path is opened through root-owned, non-writable directories without following symlinks. The source must be a root-owned, non-writable regular file of at most 256 KiB; the read is bounded and its device, inode, size, timestamps, owner and mode must remain unchanged. Only SHA256 is exported, never source bytes or handler arguments.

After a proved source fingerprint, one fixed `/usr/bin/dpkg-query --show --showformat=${Version} apport` call has a half-second timeout inside the existing four-second source budget. Only a closed, bounded Debian package-version token is exported. A package version describes installed package metadata, not proof that the handler matches upstream package bytes. Unavailable, malformed, changed or untrusted evidence remains unknown. The two existing one-second Docker identity reads and all original restart-source budgets remain unchanged. No handler invocation, core capture, process signal, runtime change or production write is added.

Focused Python regressions execute the actual command under isolated file/process boundaries and cover trusted fingerprint/version success, path/symlink/owner/mode/size/change refusals, package timeout/malformed version, closed exports and unchanged Docker identity checks.
