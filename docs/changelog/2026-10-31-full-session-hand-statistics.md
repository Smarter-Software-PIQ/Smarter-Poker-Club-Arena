# Full Session Hand Statistics

Player Hub displayed a browser observation sample as the tournament total. Kingfish's Saturday Mystery hand history and per-hand facts both held 56 completed hands at the screenshot time; the browser panel displayed 17. Current main preserves counters through confirmed table moves, but a browser reload, a backup older than one hour, or missed events still cannot recover a full tournament.

Player Hub, Full Session Stats, its detailed hand metrics and final session/tournament cards now read one self-only database snapshot. Tournament scope includes every table in the event. Cash scope uses the durable sitting's open/close timestamps and confirmed occupancy move receipts, including a move back to an earlier table. History and facts are deduplicated by hand ID; retained facts survive history pruning. Missing action facts leave VPIP/PFR unknown instead of calculating rates over an incomplete denominator. The read has no browser lifetime or row cap. It never changes player, game, hand or financial records.

Reads run on open, reconnect, visibility return, completed hand, confirmed session end and the existing TABLE_UNLOCKED settlement event. Lightning rooms retain their existing pool-session aggregate. Final cash cards bind the sitting before leave, so a later sitting at the same table cannot replace their counts. Tournament duration begins at actual play or late registration, rather than advance registration. The presentation completion event precedes persistence; unlock follows the original transaction and refreshes the final hand without requiring another deal. Late requests cannot overwrite a newer snapshot or cross table/account boundaries. Existing artwork and financial calculations remain unchanged.

Validation includes isolated PostgreSQL 17 execution with 1,205 tournament hands across tables, cash A-to-B-to-A moves with removed source seats, independent concurrent table exclusion, closed/fresh sittings, Diamond custody, incomplete fact coverage, replay and permissions; hook tests exercise loading, failures, reconnect, final settlement and stale asynchronous results. The required accounting workflow executes the maintained SQL test through the existing Data Console PostgreSQL step. See CHECKPOINT-full-session-hands.md for exact delivery state and evidence.
