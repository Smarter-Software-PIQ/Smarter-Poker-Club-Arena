# Release observer keeps immutable prior sources

The canonical HTTPS fetch changes the transaction source digest. The retained-refusal reader now admits that exact current transaction/producer pair and preserves the previous current pair alongside every earlier supported pair. No diagnostic record schema, access rule or execution authority changes.

Historical reader fixtures had copied current control files into a fixed historical generation and reconstructed an older transaction by deleting one block. Subsequent transport and installer edits invalidated those historical inputs. The fixtures now retain the exact protected historical blobs as inert test data, verify their original digest pins, and keep current-source and tampering coverage. The actual 190-case native reader wrapper passes locally; its four existing Linux-specific cases remain provider qualification on macOS.
