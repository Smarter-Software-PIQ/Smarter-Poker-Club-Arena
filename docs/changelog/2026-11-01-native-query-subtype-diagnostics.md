# Closed native query subtype diagnostics

The controlled C-contract compile site additionally emits only a closed category
when its actual error bytes contain a fixed GCC warning-as-error token; all other
compiler output remains UNCLASSIFIED. Raw output is never retained or published.

The existing private diagnostic channel now uses D3 with a fixed subtype nibble
inside the same12-byte frame. Four aggregate object/query buckets remain, with
additional bounded per-subtype started/completed request counts and elapsed/max
timings. Function/sequence batch sites use fixed codes; exact pinned SQL prefixes
classify stock singleton/aggregate/column-ACL/view/partition/foreign-option/type/
extension/PREPARE readers. Unsupported or context-incompatible text stays UNKNOWN.
No SQL, OIDs, names or result rows are recorded. No extra events are emitted.

Independent Node and Python decoders retain D1/D2 support and require valid closed
D3 codes, object/query pairing, type compatibility, monotonic time and original
record/512KiB/45-second bounds. Real compiled C production validates all14 fixed
categories and prefix near-miss handling against both decoders, including timing
agreement, partial spans, malformed frames, scope mismatch and exact byte limits.
Current native capability requires actual D3 frames and source-bound subtype
qualification; old native manifests are refused.

Sequence/function shared128-result/128MiB caps, sequence DATA byte equality,
stock rendering/ACL/snapshot paths and full native SQL parity remain unchanged.
This adds attribution for the next capture, not evidence that sequences caused
any historical timeout or a guarantee that the next capture will finish. Linux
native qualification and any changed capture remain separate ROOT-owned steps.
