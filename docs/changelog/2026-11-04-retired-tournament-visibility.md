# Remove the owner-retired tournament cohort from player views

The owner permanently withdrew exactly 145 frozen events (the original 140 and five additional events). Running database rows, cached lists, restored seats and bookmarks could continue presenting those events as playable while canonical retirement was pending.

A shared source policy excludes those immutable event IDs and their 456 verified child-table IDs from tournament services, lobby lists and counts, direct entry, satellite cards, tournament announcements, table tabs and login restoration. Table entry rejects known retired IDs before live engine hooks mount. Relationship checks cover additional children. Other tournaments, cash tables and Lightning admissions retain their existing behavior.

The eagerly loaded table service imports that policy inside its existing asynchronous reads, before returning a table or resolving a tournament table. This keeps the cohort data out of the first-paint bundle while preserving every retirement check.

This is player visibility retirement, not a claim that the canonical financial settlement or engine shutdown has completed. It does not move chips, release seats, rewrite receipts or manufacture a completed tournament status. Already loaded older clients need the new client or actual server closure; static publication alone cannot replace their running code.

Regression coverage checks exact manifest parity, table membership, preserved unrelated games, list counts, direct service reads, and real React route admission before live effects mount.
