# Recover an original process whose maintenance owner has retired

The four-minute census compatibility path can finish original table custody and
stop the original maintenance lifecycle while that same process still answers
healthy. The old sealed-image recovery reused such a running process, although
its stopped maintenance object cannot start again.

Recovery now accepts only the owning run's immutable certified profile and the
native marker written after all original custody readbacks and the empty live
engine census. The marker describes entry into maintenance stop, not a fabricated
successful acknowledgement. The original request, image, container, start time,
host PID and native PID1 start ticks must agree. Missing, malformed or unreadable
custody evidence refuses reconstruction. A newer native incarnation is never
replaced on the older marker's authority. The canonical engine-up path rechecks
the tuple and PID1 immediately before stopping the immutable container ID.

The focused shell fixtures cover healthy same-image reconstruction, repeat
recovery, empty fleets, lost acknowledgements, invalid custody and bindings,
private source ownership, changed PID1 and the final stop bookend. Historical
profiles retain their original recovery behavior. Installation and live
verification remain part of the owning release; source qualification alone is
not production recovery evidence.
