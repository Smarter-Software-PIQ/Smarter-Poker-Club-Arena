# Restore event triggers through their genuine fixture role context

The pure restore-plan renderer uses the maintained schema-only parser and strong SQL lexer. It verifies complete input reconstruction from the original prefix, every raw object part (including archive stream settings), and footer. Only actual `EVENT TRIGGER` blocks with schema `-` and owner `postgres` receive fixed context: load genuine Supautils once, enter `postgres`, retain the complete original block, and return to the less privileged `fixture_schema_restore_owner`. Supabase Admin event blocks and all other objects retain their original order and bytes under the default restore owner. Unknown event owners or schemas fail closed; input and applied SQL stay within 128 MiB.

The returned public receipt contains only hashes and aggregate object/event/context counts. No raw names, SQL, roles selected by the archive, owner rewrites, object exclusions or normalized bodies are emitted as diagnostics. Focused tests cover exact full-stream output, comments/dollar-body/escaped-string fake headers, stream settings, unchanged zero-event input, CRLF preservation and malformed/unknown-owner refusals. Initial absence of the new module was a failing test import; final focused checks pass. This is source rendering qualification. Genuine Linux Supautils behavior, the actual full captured restore and product acceptance remain separate owner-operated checks.
