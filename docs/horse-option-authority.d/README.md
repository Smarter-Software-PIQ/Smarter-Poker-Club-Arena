# Authority Files For The Horse Option Switch

One file per option, `<option>.md`, cited with its sha256 by the note of an option-switch `on` row (`authority: <option> <file> sha256 <64 hex>`, HorseOptionSwitch.optionSwitchOnNote). A file states what the option does, the owner's order it rests on (verbatim), the recorded hands it answers, its receipts and tests, and which evidence rows of docs/HORSE-DECISION-CHANGE-EVIDENCE.md are met. These options are OFF in source; this directory is not docs/horse-default-on.d (source-default evidence).

Replay bar (2026-11-18). An option that changes a Horse decision carries, under its evidence rows, one line per audit source for each arm it was replayed in, written by the committed scorer and copied unedited: `npx tsx scripts/audited-decision-replay.ts --audit2 <decisions.csv> --audit2-hands <hands.jsonl> --woowoo <decisions-full.csv> --woowoo-findings <decision-to-finding.csv> --replay <replay.jsonl> --line <arm>` (run from server/; src/benchmark/AuditedDecisionReplay.ts). The line is joined by decision node (hand, seat, street, the seat's own decision index on that street), never by position, and states: decisions audited and replayed, nodes not replayed, how often the base arm reproduces the recorded action; changes (more aggressive / more passive), resizes, illegal, refused, errors; fixed, newly wrong, still wrong, ok to ok, unjudged; audited-bad decisions left unchanged; the audit model's EV difference in bb where the audit has one (audit2) and "no bb" where it declares none (the WooWoo audit, scored verdict-only); and the same counts per rule receipt. What the line must show to pass is declared in the option's PASS-BAR before the replay runs; the line itself only reports.

The Replay row (2026-11-19). The replay on real audited decisions is a required, recorded bar. Every option file (`<option>.md`; not this file, not a supplementary `<option>.<PART>.md`) carries, under a `## Replay` heading, machine-read rows read by `server/src/engine/EveryHorseOptionRecordsItsReplay.law.test.ts` with the scorer's own parser (`parseReplayBarRows`):

- Replay: fixed N; newlyWrong N; changed N; unchanged N; unjudged N; set <name of the audited decision set>; scorer <commit>; source <audit and method>; arm <arm> vs <base>; replayed <n> of <audited>
- Replay: NOT RUN (<reason>)
- Replay: LEGACY (<reason>)

(The three lines above are the format, read by the law as text of this file; this file is not an option file.) A run row is one audit source of one replay, off against on, and is printed by the scorer: add `--row <arm> --set <name>` to the command above and copy the row unedited. `fixed`, `newlyWrong`, `changed`, `set` and `scorer` are required; one row per set and source. NOT RUN gives the reason. LEGACY marks a replay that this file records in prose only, from before the row existed: it is not a run row and satisfies nothing. A file has run rows, or one NOT RUN or LEGACY row.

What the build enforces. A file whose status paragraph (the first paragraph under the title) contains "Evidence MET" claims that the option is eligible for switch-on; every other wording does not, and a status paragraph may not say MET without "Evidence MET" or "Evidence NOT MET". A file that claims "Evidence MET" must carry run rows, and in each of them newlyWrong must not exceed fixed: NOT RUN, LEGACY, or more decisions newly wrong than fixed fails the build. The files that claimed "Evidence MET" on 2026-11-19, before the row existed, and were switched on in production that day (read 2026-11-19T19:00:33Z) are listed by name in the law (GRANDFATHERED_20261119: omahaPreflopReraiseDefencePricedInPosition, omahaSmallBetIsPriced, omahaTurnRiverRaiseIsPriced); the list is closed and an entry leaves it with its first run row. omahaReadIsByStreetAndTexture claimed it too but was not on and its own file holds its switch-on, so its status paragraph now states "Evidence NOT MET" and it is not listed. The option's PASS-BAR may ask for more than the build does; it may not ask for less.

What the scorer refuses (exit 2, nothing scored). A replay of journaled decisions hands the brain the option set each record carries, and today's registry refuses a set as a whole when it names an option that is off-only or unregistered today: nothing is switched and every arm plays the release defaults (the flop-read replay of 2026-11-19 first produced four identical arms that way). The harness therefore declares the option set it handed the brain, per arm on a line `{"meta": {"arms": {"<arm>": {"options": {"<option>": "on" | "off"}, "sanitized": {"<option>:on>off": <rows>}}}}}` or per row as `arms.<arm>.options`, after setting an off-only option off (as production holds it today) and dropping an unregistered one. The scorer refuses a declared set the registry refuses, an arm identical to the base arm on every compared row unless it is declared with `--allow-unchanged <arm>`, and `--row` from arms whose option set is not declared. Two more limits of journal replay that the scorer cannot see and the file must state: a read frame journaled before the street-record migration (20261117175407) carries no street read, so an option that reads it is inert unless the record is rebuilt (say so, and how); and an option absent from a declared set runs at its release default, which is not always off.

The PLO6 audit set (2026-11-20). The scorer also reads the PLO6 audit set (HVH48 auditor C, six-card Omaha) in its own three files: `--plo6 <decisions.csv> --plo6-meta <meta.jsonl> --plo6-hands <hands.jsonl>` (`plo6Decisions` in src/benchmark/AuditedDecisionReplay.ts), alone or beside the other sources. From decisions.csv it reads `id` (`d<n>`), `hand` (the hand_history id), `street`, `action`, `status`, `severity` and `mistake`; from meta.jsonl the object with `n` = N for decision dN, fields `hand`, `street`, `act`, `seat`, `t`; from hands.jsonl (raw hand_history rows) `id`, `game_variant` and `actions[].{action, amount, origin, seat, stage, timestamp}`. A row is placed when its meta row exists and agrees with it on hand, street and action, the hand is `plo6`, and exactly one `horse_policy` action has the meta seat, street, timestamp and action; the node's k is counted as for audit2. Verdicts (the coordinator's decision of 2026-11-20): `priced` with severity `CLEAR` or `LIKELY` is bad; `priced` with empty mistake and empty severity is ok (the auditor priced it and found no mistake); `priced` `DEBATABLE` and every `unpriced` row are unjudged; any other combination is not placed. `mistake` is kept as the finding. A row it cannot place is listed with its reason, exit 1, and is never placed at a neighbour. Scoring is verdict-only, as for the WooWoo audit (no bb). No card is read or kept: the csv's `hole` and `board`, meta's `hole`, `board` and `humans`, and the hands' `players[].cards`, `hole_cards` and `community_cards` never enter a node, a report or a row. `--emit-nodes` adds the audit's `id` and `actionIndex` (the action's index in the hand's actions array) to each PLO6 node for the harness. The harness replays with seeds; the scorer takes one action per arm per node, so each seed is its own replay file and its own row, with the seed in the set name.

The placed source (2026-11-20). The scorer read two audit sets (audit2, the WooWoo audit). An option that answers another audit is replayed on that audit's decisions placed at their node by a committed placer and read with `--placed <nodes.jsonl>` (one JSON line per audited decision: hand, seat, street, k, recorded, verdict, cls, better). `server/scripts/hvh48-audit-nodes.py` places the six HVH48 audits of 2026-11-19 (bad = severity CLEAR or LIKELY, ok = priced and not flagged, the rest unjudged) and `server/scripts/audited-node-option-replay.ts` re-decides the nodes with a live switch set off against the set plus the option, declaring both sets. A placed source is scored verdict-only, and where the audit names the better action a change away from a judged-bad action is fixed only when it is a change to that action; the row reads `source placed verdict-only` and its `set` names the audit.
