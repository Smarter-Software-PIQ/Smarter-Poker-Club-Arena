## What "dead" means here, and what it does not

The ablation's zero is a zero on its test sets, not proof that a rule never acts in production. Four things make a
rule read as dead there while it is live:

1. **Read-gated.** The rule acts only once an opponent read (style label, call-down tally, limp-reraise rate, probe
   discount, exploit modifier) has formed. The replay states carry opponent history on one state in four, and the
   real-card set carries memory as of each decision; most reads never form there. Several of these rules change
   actions live (style counters below).
2. **Worker runtime only.** The live worker's observer reads put the evidence into the decision's detached state
   (`server/src/engine/horseDecision/observerReads.ts`, `workerRuntime.ts` `readViewOpts`). The replay calls
   `HorseLogic.decide` directly, so this path is not exercised at all (ablation section 10).
3. **Untested format / not Hold'em.** Bounty, prize-jump, satellite, spin and straddle games are absent from every
   test set, and some names the ablation listed act only in Omaha. These are marked **untested format** or
   **Omaha only**, not dead.
4. **Pre-empted.** While `holdemValueAndCallsArePriced` was on (until 2026-11-24T06:07:29Z) it answered heads-up cash
   postflop first and pre-empted several blanket shades (ablation section 4). It is off now, so those need a retest.

Before any retirement: confirm the off arm really reached `decide()` with the option off (its receipt count falls to 0
in the off arm). Several default-on rules below fire tens of thousands of times a week live and still show 0 changes,
which is worth one harness check before reading it as "does nothing".
