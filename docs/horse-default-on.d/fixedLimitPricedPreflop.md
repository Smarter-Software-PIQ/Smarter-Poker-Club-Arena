## Mechanism

`HorseLogic` builds `fixedLimitPriced` for a fixed-limit preflop decision inside the option's scope (`fixedLimitPreflopInScope`: a CASH table, `!isTournamentMode(gs)`, whose variant, floor (`gs.vpipFloor > 0`) and dealt seat count (`dealtHorseTableSize`) are on the frozen allow-list `FIXED_LIMIT_PRICED_PREFLOP_CREDITED`; no bomb pot, no all-in-or-fold, no straddle) when the option is on, and `HorsePreflop.decidePreflopV7` takes three paths from `HorseFixedLimitPreflop.ts`:

1. First in: the seat raises its reference share by players behind (flh 45 / 31 / 24 / 19 / 15 / 13 % for 2 / 3 / 4 / 5 / 6 / 7+ behind; flo8 38 / 28 / 22 / 18 / 15 / 13 %); the small blind folded to raises a band and completes a further band (flh 40 / 65 %, flo8 30 / 60 %); the heads-up button raises flh 85 % / flo8 70 %. Persona tightness moves a share by at most 5 % of itself. Receipt `fixed_limit_priced_first_in`.
2. Blind facing one raise: call when equity (hero bucket vs the opener's reference range, generated table) x realization (flh 0.65, flo8 0.55, calibrated to published defence widths at the raw price) x 0.85^(players behind) covers the RAW pot price call / (pot + call). Rake enters once, through the calibration (fix df1acb46: the earlier rake-deducted price counted rake twice). The option never turns a blind's continue into a fold. Receipt `fixed_limit_priced_blind_defence`.
3. Under the same option, again only inside the same scope (`fixedLimitPreflopInScope` on the precedence argument to `evaluateRemainingVariantPolicy`), the phase12 pack's three round-3 first-in rules (open tightened, heads-up open, small blind steal) retain this reference in fixed limit (receipt reason `fixed_limit_priced_retains_<rule>`); the big-blind rule is no longer held (fix df1acb46).

## OFF and rollback contract

- Source default OFF: with no row, every Horse decides exactly as main does today. At a tournament table every Horse decides as main does whatever the row says (cash-only gate). At a cash table type off the allow-list every Horse decides as main does whatever the row says.
- OFF, live: `SELECT public.fn_ca_horse_option_switch_set('fixedLimitPricedPreflop', 'off', '<actor>', '<note>')` as service_role (audited in `ca_horse_style_switch_audit`); clearing the row returns to the source default. While the option is off-only (the owner preflop range hold) the switch refuses 'on'; after a lift recorded in `OPTION_SWITCH_PREFLOP_HOLD_LIFTED` and its list migration, 'on' and 'off' are both accepted. The main thread reads the table every 30 s and passes the switched options to every decision worker with each decision; a hand in progress takes the new value at its next decision.
- When a row may be written (Hand Analysis 2026-11-15 20:17:42Z item 4 as corrected 20:42:45Z): only after every serving engine instance (all workers, any canary) reports a build that carries `fixedLimitPricedPreflop`; never while an older build is still serving anywhere (mid-cutover); before any rollback to a build that does not carry the name, clear this row first, because one name an engine does not know makes its whole switched set invalid and every non-style option on that engine then runs at its release default.
- Nothing is persisted by the option: it changes preflop actions only, reads no stored profile and writes none.
- `fixedLimitStealVsTightBlinds` accepts only 'off' (off-only) until the owner lifts the steal hold by name.
