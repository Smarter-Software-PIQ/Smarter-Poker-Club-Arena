## Mechanism

`HorseLogic` builds `fixedLimitPriced` for a fixed-limit preflop decision inside the option's scope (`fixedLimitPreflopInScope`: a CASH table, `!isTournamentMode(gs)`, and in hi-lo an unfloored table, `gs.vpipFloor` not above 0, dealt three seats or more; no bomb pot, no all-in-or-fold, no straddle) when the option is on, and `HorsePreflop.decidePreflopV7` takes three paths from `HorseFixedLimitPreflop.ts`:

1. First in: the seat raises its reference share by players behind (flh 45 / 31 / 24 / 19 / 15 / 13 % for 2 / 3 / 4 / 5 / 6 / 7+ behind; flo8 38 / 28 / 22 / 18 / 15 / 13 %); the small blind folded to raises a band and completes a further band (flh 40 / 65 %, flo8 30 / 60 %); the heads-up button raises flh 85 % / flo8 70 %. Persona tightness moves a share by at most 5 % of itself. Receipt `fixed_limit_priced_first_in`.
2. Blind facing one raise: call when equity (hero bucket vs the opener's reference range, generated table) x realization (flh 0.65, flo8 0.55, calibrated to published defence widths at the raw price) x 0.85^(players behind) covers the RAW pot price call / (pot + call). Rake enters once, through the calibration (fix df1acb46: the earlier rake-deducted price counted rake twice). The option never turns a blind's continue into a fold. Receipt `fixed_limit_priced_blind_defence`.
3. Under the same option, again only inside the same scope (`fixedLimitPreflopInScope` on the precedence argument to `evaluateRemainingVariantPolicy`), the phase12 pack's three round-3 first-in rules (open tightened, heads-up open, small blind steal) retain this reference in fixed limit (receipt reason `fixed_limit_priced_retains_<rule>`); the big-blind rule is no longer held (fix df1acb46).
   Pinned by `AFixedLimitPreflopIsPriced.law.test.ts` (24 tests at df1acb46, 6 failing before the fix; 28 with the cash-only describe), with production-shaped rake (10 %, cap, jackpot fee 0.6 bb) in the test tables. The steal (`fixedLimitStealVsTightBlinds`) shares the same entry condition in HorseLogic, so it is behind the same cash gate and the same hi-lo scope. The hi-lo scope block of the law (Phase 2) pins the gate: 36 tests at its head; removing the hi-lo half of the gate fails its three inert cases.

## Scope

CASH TABLES ONLY, BY CODE. Every P branch (the priced first in, the blind defence, and the pack precedence) is gated on `!isTournamentMode(gs)` in `HorseLogic.ts`: the same cash/tournament test every other cash/tournament split in HorseLogic uses (it trusts the table engine's explicit `gameMode`, which `ServerTableEngineTurns` sets from `isTournamentTable()`). The steal shares the same entry condition and is gated with it. Law (`AFixedLimitPreflopIsPriced.law.test.ts`, "cash tables only"): at flh and flo8 tournament tables (100 big blinds, so the 20-big-blind short-stack rule is not what holds the answer) every first-in decision (six-max UTG to small blind, heads-up button) and every big-blind decision facing one raise (six-max and heads-up) with the option on, and with the steal on too, equals off, and no W5 receipt fires; on the same spots and seeds at cash tables the option still changes first-in and big-blind decisions and its receipts fire. With either gate removed the tournament half fails at the first deal.

HI-LO SCOPE, BY CODE (Phase 2, 2026-11-16; owner order 2026-11-16T04:08Z to build, fix and enhance; AB-EVALUATION-2 0.18). `fixedLimitPreflopInScope` (HorseLogic.ts, beside `dealtHorseTableSize`) returns false at a tournament table, and in hi-lo also at a table dealt two seats (`dealtHorseTableSize`, the dealt-seat count the W5 tables already use) or a table with a VPIP floor (`gs.vpipFloor > 0`, the table's `maintain_percent_min`, the same test the VPIP floor rule itself uses). Both P contexts and the pack precedence read it, so at flo8 heads-up (floored or not) and at a floored flo8 table of any size every Horse decides exactly as with the option off. Reason: the harness cannot validate those table types (AB-EVALUATION-2 2.3: flo8 heads-up big-blind defence not judged; floored flo8 six-seat big-blind defence NOT VALID), so no paired result can support them. Hold'em is not narrowed. Law block "hi-lo scope" (`AFixedLimitPreflopIsPriced.law.test.ts`): at flo8 heads-up unfloored, flo8 heads-up floored and flo8 six-max floored, every first-in and big-blind decision with the option on (and with the steal too) equals off and no W5 receipt fires; at flo8 six-max unfloored and at flh 2/6/9, floored and unfloored, the option still changes decisions and fires. - Source default OFF: with no row, every Horse decides exactly as main does today. At a tournament table every Horse decides as main does whatever the row says (cash-only gate).
- ON and OFF, live: `SELECT public.fn_ca_horse_option_switch_set('fixedLimitPricedPreflop', 'on' | 'off', '<actor>', '<note>')` as service_role (audited in `ca_horse_style_switch_audit`); clearing the row returns to the source default. The main thread reads the table every 30 s and passes the switched options to every decision worker with each decision; a hand in progress takes the new value at its next decision.
- When a row may be written (Hand Analysis 2026-11-15 20:17:42Z item 4 as corrected 20:42:45Z): only after every serving engine instance (all workers, any canary) reports a build that carries `fixedLimitPricedPreflop`; never while an older build is still serving anywhere (mid-cutover); before any rollback to a build that does not carry the name, clear this row first, because one name an engine does not know makes its whole switched set invalid and every non-style option on that engine then runs at its release default.
- Nothing is persisted by the option: it changes preflop actions only, reads no stored profile and writes none.
- `fixedLimitStealVsTightBlinds` accepts only 'off' (off-only) until the owner lifts the steal hold by name.
