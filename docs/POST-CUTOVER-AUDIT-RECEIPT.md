# Post-Cutover Audit Receipt

Since November 26, every engine receiver run that was started by a cutover (a `repository_dispatch`) is followed by `.github/workflows/post-cutover-receipt.yml`. It finds that run's `Cycle:`/`Result:` comment on #11599, runs `scripts/ops/post-cutover-audit.mjs` against production read-only (psql in a read-only transaction, through `--db-url-env`, with the sealed SHA as the expected release), and replies on #11599 with `Post-cutover audit for receiver run <id>` and every check's verdict. If only live health fails while the engine settles, it re-audits once after 90 seconds. A receipt never starts with `Cycle:`, never carries a `Result:` or `Sealed SHA:` line, and is posted once per receiver run, so the release tools that read the log cannot mistake it for a cycle result. The workflow only reports: it has no schedule, cannot dispatch or deploy anything, and asks for `contents: read` and `issues: write` only. To re-post a receipt by hand, run the workflow with `receiver_run_id`. Tests: `tests/unit/postCutoverReceipt.test.ts`.
