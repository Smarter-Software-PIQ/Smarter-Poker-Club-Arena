# server/src/engine/upgradeEvidenceGuardAndUse.law.test.ts

The per-Horse upgrade evidence judges upgrade 09 (pre-action purge) as a GUARD and counts upgrade 04 (Omaha reservoir) where it is used, and neither changes a decision. Upgrade 09 is the one entry in `HorseUpgradeEvidence.PER_HORSE_GUARD_UPGRADES`: the brain decision fold credits it nothing (even with its own counters in the fires); each host opportunity (a server-owned Horse reaching its turn with a pre-action armed) is one decision, and one invocation only when the pre-action is gone after the clear; `judgeHorseUpgradeEvidence` reports a guard with no opportunity and one that acted every time as healthy and one with an opportunity it did not act on as flagged, and `scripts/ops/per-horse-upgrade-evidence-daily.sql` lists the same guards with the same three verdicts. Both hosts (`ServerTableEngineTurns`, `LightningHandHost`) fire the opportunity counter apart from the purge counter and pass the outcome to the per-Horse event. Upgrade 04's needle is the per-decision use receipt `upgrade04_reservoir_used_seen`, fired once by `workerRuntime.executeFastWithUpgradeEvidence` inside the fire scope after `executeFast` has returned when `HorseEval.omahaReservoirReadsTotal` moved; every reservoir read moves that integer by one; nothing else reads it; the build counter stays a separate build receipt. Seeded Omaha percentiles, band placements and banded equity are identical with telemetry armed and disarmed and whatever the counter stood at. Guards against a guard read as a dead upgrade against every brain decision, a guard that stops acting without a flag, and an upgrade's "invoked" counting worker starts instead of decisions.
