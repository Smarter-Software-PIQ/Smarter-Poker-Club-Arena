# server/src/engine/HorsePerHorseUpgradeEvidence.law.test.ts

The decision worker records, once per FAST decision, which approved upgrades that Horse's decision exercised (`workerRuntime.executeFastWithUpgradeEvidence`, `BrainTelemetry.withDecisionFireScope`, `HorseUpgradeEvidence.noteHorseUpgradeDecision`), and recording it changes nothing. Through the real `HorseDecisionWorkerRuntime` and the real brain on controller-dealt states: two Horses in different variants and lanes produce rows carrying their own id, variant, lane and upgrade ids, with `invoked` equal to the upgrades whose evidence counters that same decision fired for the fleet; an execution that throws records no decision and leaves nothing for the next Horse; the same seeded request returns the identical FAST_RESULT (decision, receipts, RNG before and after) with the scope collecting and with a pass-through; the worker opens one scope and folds at one site, with DEEP outside it; and a counter maps to an upgrade only by the manifest's needle rule (quoted needle = exact name, backtick needle = prefix). It also pins the no-double-count rule (no host event beside a decision-request counter or an insurance answer, exactly one beside each host opportunity; a side game the brain read in a decision is that one decision invoked by the worker fold) and that both processes start the flush with their telemetry and stop it in the telemetry stop's parallel slot. Guards against per-Horse evidence that is attributed to the wrong Horse, counts shadow or DEEP evaluations, leaks between decisions, or perturbs a decision.
