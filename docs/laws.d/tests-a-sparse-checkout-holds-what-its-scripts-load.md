# tests/a-sparse-checkout-holds-what-its-scripts-load.law.test.ts

Every workflow job that sparse-checks-out this repository holds, in its working tree, every tracked file the scripts it runs load from the working tree (Python `spec_from_file_location`, `runpy`, `with_name`, `parents[N]` and `sys.executable` subprocesses; ESM relative imports), judged by `git sparse-checkout check-rules` in the job's own cone or non-cone mode. On 2026-11-09 the Stage `selection` job (sparse `scripts/ci` and `server/scripts`) ran `select-daily-engine.py`, whose helper `engine-release-installed-migrations.py` (#10114) loads `server/standby/schema-evidence.py` from disk; the file was absent, so daily selection 42562159686 froze `blocked` while every full-checkout test passed. A file read through `git show <sha>:<path>` is not a load. A recorded exception names one file reachable only from a subcommand the job never runs, with its reason, and fails if it is no longer reachable or no longer absent.
