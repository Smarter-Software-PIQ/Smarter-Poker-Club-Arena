# server/src/engine/horseDecision/everyUpgradeHasALiveSwitch.law.test.ts

The Horse option switch carries only registered decision options, fleet-wide, and does nothing until a row is set: the database whitelist equals the engine registry; authority-gated options, phase packs, Pillar 2, R7/R8, held-out packs, All-In-Or-Fold widening, blind steal, the withdrawn PLO6 rules and preflop range changes are refused by name by the registry, the database functions and the worker; a real decision with an empty switch is handed exactly what it was handed without one; set and clear write the audit table with actor and time and only service_role may call them; an unreadable or malformed read leaves every option at its release default; a replayed decision uses the switched set its own record carries; and `on` is offered to a non-style option only when its evidence file docs/horse-default-on.d/<option>.md exists and binds to it by exact name, pull request, measured scope (switch scope equal to the registry scope, variants, formats), reviewed head and the digest of the option's code path, which goes stale on any change to that path (HA-10878-1), with the registry, the parser, both SQL functions and the table all refusing an un-evidenced `on` (proven on a throwaway PostgreSQL 17 in the required accounting_postgres job); and a started, restarted or replaced decision worker resolves the persisted switch state before it serves a decision that reads a switched option.
