# tests/an-alert-resolution-reaches-its-incident-once-per-statement.law.test.ts

The alert->incident roll-up (zz_ca_alert_resolution_reaches_the_incident) runs once per UPDATE statement with transition tables and reads the resolved set once into a keyed jsonb lookup, so resolving N alerts against an M-member incident costs O(N + M), never N x M (incident 075013fd: 7,693 members x 4,957 alerts rolled every closer run back at its timeout). Closure is unchanged: 'verified_remeasured' exactly when the last member resolves. The settled-alert closer (job 354) runs as a procedure that COMMITs each bounded page, so a slow page never rolls back earlier ones. Native proof: scripts/ci/test-an-alert-resolution-reaches-its-incident-once-per-statement.py.
