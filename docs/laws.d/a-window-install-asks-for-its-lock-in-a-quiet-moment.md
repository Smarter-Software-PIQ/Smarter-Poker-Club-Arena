# tests/a-window-install-asks-for-its-lock-in-a-quiet-moment.law.test.ts

Before its one attempt at a daily-maintenance window file, scripts/ci/install-window-migrations.mjs reads pg_locks (read-only, requesting no lock) for exactly the relations the file will lock and waits for no conflicting holder older than 250 ms, bounded by a deadline derived from the release's admission certificate (40 s into the break, less the measured PostgREST reload and one door poll); when the bound passes it sends the file once anyway, so the 1 s lock_timeout, one-attempt and stop-at-first-refusal rules are unchanged, and a refusal names who held the tables. On 2026-11-07 the first queued file was refused 55P03 in the same second the top-of-the-hour pg_cron burst started, holding the hit-and-run migration the next engine needs for a day.
