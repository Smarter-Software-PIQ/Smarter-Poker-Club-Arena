# tests/a-merged-migration-is-dispatched-by-its-merger.law.test.ts

Every protected merge dispatches the migrations it added or modified, whoever merged it: `dispatch-merged-migrations.yml` (its own workflow since 2026-11-07, #9994; Agent Autopilot is disabled) reacts to the native `closed` event of any same-repository PR merged into main, with the job token, and sends one `apply-merged-migration` repository_dispatch per added or modified `supabase/migrations/*.sql` (modified since 2026-11-08, #10026/#10029: a migration refused at install and fixed in place; the applier answers ALREADY-APPLIED, sending nothing, for an installed version; a removed file or a rename's old name is never sent), in filename order, `dry_run` false, never retried. `-- @install-window: daily-maintenance` files are skipped by the applier's own classifier and named in the summary as queued for the daily window route. Inside the :50-:03 UTC window, the daily 04:00 Chicago break, or the nightly release schema freeze (23:45-04:15 Chicago, 2026-11-17, `tests/an-ordinary-migration-waits-for-the-daily-engine-selection.law.test.ts`) the job waits once, bounded (22 minutes; 285 minutes for a freeze hold), before sending anything; beyond the bound it sends nothing, names every file in the summary and on the PR, and fails. `apply-merged-migration.yml` stays dispatch-only.
