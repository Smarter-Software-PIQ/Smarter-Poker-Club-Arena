# tests/the-horse-fleet-measures-its-stuck-horses.law.test.ts

On 2026-11-18 the daily digest said "Horse fleet degraded on 1 heartbeats; stuck-horse count unavailable" and the reliability controller escalated it. The stuck count had never been measured: every `ca_horse_fleet_heartbeat` row for more than 40 days carried `horses_stuck` NULL, because HorseFleetManager sends it as null on purpose and nothing filled it. A degraded beat only means one cycle ran on the built-in fleet policy defaults, yet the digest fired on any one of them (1 of 2,635). This law pins that `fn_ca_fleet_state_upsert` measures the count through `fn_ca_horses_stuck_now()` when the engine sends none, in its own subtransaction, so a failure stays NULL rather than 0 and never costs the heartbeat. The count is read from the engine's commit record (`hand_history` players and actions), never from `ca_horse_fleet_state.last_action_at`: that stamp is a batched seat touch, and on 2026-11-18 it froze at a table that committed 55 more hands with the same horses in every one. A horse counts only when it held its live seat for the whole window (seated before it, with no seat exit or seat move into the table inside it, since a seat move copies `joined_at`), was neither sitting out nor waiting for the big blind, and its table dealt three or more hands that either left it out entirely or recorded only timeouts for it. The law also pins that the digest pages on a run of `horse_degraded_run` consecutive fallback cycles, and that every later rewrite of these functions carries all of this.
