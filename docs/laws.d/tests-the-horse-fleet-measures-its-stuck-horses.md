# tests/the-horse-fleet-measures-its-stuck-horses.law.test.ts

On 2026-11-18 the daily digest said "Horse fleet degraded on 1 heartbeats; stuck-horse count unavailable" and the reliability controller escalated it. The stuck count had never been measured: every `ca_horse_fleet_heartbeat` row for more than 40 days carried `horses_stuck` NULL, because HorseFleetManager sends it as null on purpose and nothing filled it, while `ca_horse_fleet_state` (written by the same RPC a moment earlier) holds a current `last_action_at` for every seated horse. And a degraded beat only means one cycle ran on the built-in fleet policy defaults (today's behaviour), yet the digest fired on any one of them: 1 of 2,635 that day. This law pins that `fn_ca_fleet_state_upsert` measures the count through `fn_ca_horses_stuck_now()` (a seated horse silent for `horse_stuck_minutes` while its own table dealt) when the engine sends none, in its own subtransaction so a failure stays NULL rather than 0 and never costs the heartbeat. It also pins that the digest pages on a run of `horse_degraded_run` consecutive fallback cycles rather than a single one, and that every later rewrite of the three functions carries both.
