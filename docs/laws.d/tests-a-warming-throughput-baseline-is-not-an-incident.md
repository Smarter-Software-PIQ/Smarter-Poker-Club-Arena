# tests/a-warming-throughput-baseline-is-not-an-incident.law.test.ts

HorseFleetThroughputBaselineWarming reports that the relative cash-throughput check has fewer than three same-policy historical days. That is a designed warm-up after every change to the admission cohort (the full text of thirteen SQL functions plus the engine population fingerprint), and its own description says the zero-dealing and table-stall alarms stay independent. The broad reliability class `Horse%` nonetheless made it an incident, so from 2026-11-16 to 2026-11-18 a warm-up that only time can end was escalated to the owner as "no eligible recovery". This law pins a class row, ahead of `Horse%`, that classifies exactly this alertname as not an incident. It also pins that the install proves the throughput alarms needing action (HorseFleetThroughputPolicyUnknown, HorseFleetThroughputRelativeDrop) stay incidents and that a resolved warm-up still reaches its open incident, and that no later migration reverses it.
