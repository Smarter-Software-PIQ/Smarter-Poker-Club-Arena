# tests/the-daily-date-follows-the-release-controls.law.test.ts

The daily engine preparation date belongs to the first stage-engine-release.yml run reserved under the release controls the cutoff binds. An earlier run in the reservation window whose source carries the same release-authority projection still owns the date, and later runs defer to it. An earlier run whose source carries different release controls (for example, an owner-window booking merged during the five-hour reservation) is not an owner: it will refuse at its own cutoff, so the first run carrying the new controls prepares. A projection that cannot be read (no head_sha, unknown commit, missing reader) keeps the earlier owner. The cutoff refusal "Release controls changed during reservation; keep serving." is unchanged, so nothing runs under older release authority, and no timer, retry, watcher or second dispatcher is added.
