# server/src/engine/IcmEstimatorReuse.law.test.ts

TASK #8 (Horse SWITCH lane, 2026-11-20): the tournament-utility node took 44% of all Horse decision time on production (about 26.5 ms per tournament decision; NLH decisions 29 ms on average, cash 5-10 ms, tournaments 25-100 ms), and every tournament decision rebuilt the Monte Carlo ICM clock population (up to 240,000 seeded exponential draws and a sort per trial over the remote field). The population is a pure function of its construction inputs, so `IcmModel.createIcmEquityEstimator` now shares one estimator between decisions whose field length, hero index, payout curve, mutable (table-local) slots, trial cap, live count and every non-mutable stack are identical, in a bounded per-process LRU. The law holds that a shared estimator returns bit-identical estimates to a fresh build for every vector and trial prefix, that a change to any construction input builds a new one, that a table-local stack change alone reuses it with values equal to a fresh build, that the cache stays bounded, and that exact (ten or fewer players) and winner-take-all estimators are never shared.
