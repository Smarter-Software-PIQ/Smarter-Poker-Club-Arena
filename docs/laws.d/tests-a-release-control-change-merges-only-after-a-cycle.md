# tests/a-release-control-change-merges-only-after-a-cycle.law.test.ts

A pull request into main that changes a file of the release-control projection (`CONTROL_INPUTS` in `scripts/ci/read-engine-prequalification.py`, minus its test and Horse research exclusions) is held by the required status `Migration merge window` to the same minutes an ordinary migration may merge (10-27 minutes after each engine cycle and 04:15-04:27 Chicago), or the written outage override. Which files are projected is read from the Python constants as text (`scripts/ci/release-control-paths.mjs`) and agrees with `projection()`'s own filter on every tracked file; an unreadable constant holds the release workflows and directories with no exclusion. The failures of 2026-11-25 22:50 Chicago (O27, the 01:00 cycle kept serving) and 2026-11-26 12:40 Chicago (the O31 batch, 13:00 kept serving).
