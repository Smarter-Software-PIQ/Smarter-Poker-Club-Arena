# tests/the-sweep-measures-a-week-only-for-a-winning-day.law.test.ts

When the union integrity sweep gained its 7-day roster measure (20261119063000), the measure sat in the same WHERE as `n.player_net > 0`, a condition on `net` alone, so the planner pushed both onto the scan of `net` and ran the 7-day measure for every agent with a positive day before the rake join could rule almost all of them out. The hourly `union-integrity-sweep` cron then timed out at 300 seconds at 10:33 and 11:33 UTC on 2026-11-19, where it had finished in about 47 seconds all day. This law pins the repair: the 24-hour test runs in a fenced subquery (`OFFSET 0`), the 7-day measure filters only its output, the change is a pinned pre/postimage substitution, and the migration runs the whole sweep for every union before COMMIT and refuses itself unless it finishes inside 90 seconds.
