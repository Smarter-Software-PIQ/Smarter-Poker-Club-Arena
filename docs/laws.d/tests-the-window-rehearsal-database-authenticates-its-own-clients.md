# tests/the-window-rehearsal-database-authenticates-its-own-clients.law.test.ts

The window-migration rehearsal restores production's schema into a throwaway supabase/postgres container and installs a pull request's migrations into it, and every client call it makes is a `docker exec ... psql` as supabase_admin or postgres. That image asks for a password even on its local socket. The container was started with POSTGRES_PASSWORD only, so every call stopped at "Password for user supabase_admin:" and failed with fe_sendauth before one migration was read: on 2026-11-18, every migration-bearing pull request (16 branches) failed the rehearsal. `docker exec` inherits the container environment, so this law pins that the container carries PGPASSWORD equal to POSTGRES_PASSWORD, and that every rehearsal client reaches the database through `docker exec` on that container.
