# tests/a-paused-migration-install-resumes-what-merged-during-it.law.test.ts

An owner engine window pauses migration installs by switching the applier (and on 2026-11-15 also the dispatcher) off, and a switched-off workflow drops the merges it misses instead of queuing them. The law pins that the resume step is `scripts/release/resume-migration-installs.sh <pause-start-sha>`: it switches both workflows back on, confirms each is active, and sends every ordinary migration added or modified on main since the pause exactly once, oldest first, never a removed file and never a `-- @install-window: daily-maintenance` file; it refuses a pause point that is not on main; and the cutover playbook names it instead of a bare re-enable (incident c1a85d20, MergedMigrationNotInstalled, fourth recurrence).
