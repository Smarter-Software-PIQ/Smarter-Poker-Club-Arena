# tests/a-superseded-post-deploy-failure-is-a-non-verdict.law.test.ts

Post-Deploy E2E `Client browser verification` takes ~90-110 minutes running the specs of `$LIVE_SHA`. When a newer protected-main commit publishes mid-run (observed on run `46108674387`: `b94db48e` specs running against `e11255d7`), version-skew failures on the older specs made the job exit `failure` and fired `PostDeployVerificationIncomplete` even though `release_window` proved production had moved forward on `origin/main`. In the same run, `leaderboard-console.spec.ts` failed `My Clubs Tournament Stats` at 1440px with `color-contrast (1)` because `leaderboardMotion.ts` omitted `.tournament-stats-entry` (animated with `animate-fade-in-up` in `LeaderboardPage.tsx`). This law pins that `classify-superseded-failure.mjs` returns exit 3 ONLY on a proved forward supersede on trusted history (same-release failures, rollbacks, off-lineage SHAs, and unreadable reads stay exit 1), that `post-deploy-e2e.yml` classifies superseded suite failures as non-verdicts without ever certifying them, and that `leaderboardMotion.ts` awaits `.tournament-stats-entry` entrance motion before contrast checks.
