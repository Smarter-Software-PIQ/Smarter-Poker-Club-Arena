# server/src/engine/HorseDecisionSpotMatrix.law.test.ts

In all nine variants and both modes, a Hybrid Horse resolved by `resolveHorseHybridProfile` and decided by the worker (`DECIDE_FAST`) on states a real `HandController` reached through real actions must answer legally in every kind of postflop spot: facing a bet, a raise and an all-in, first to act, on the flop, turn and river, heads-up, three-handed, six-handed and full ring, short-stacked with the all-in button as its only raise, and on a capped fixed-limit street. Each answer must be a `FAST_RESULT` with a valid receipt and no fallback, on the controller's menu, inside the controller's minimum and maximum (whole chips in tournaments), accepted by `performAction`, with the per-decision upgrade counters the manifest declares (01, 02, 06; 07 in tournaments) fired exactly once. The controller's bounds are checked against the betting structure (no-limit the stack, pot-limit the pot, fixed limit the one street size), and every action the controller offers is executed on a twin of the same hand, so fold, check, call, bet, raise and all-in are each proven offered and accepted in every structure. Guards against a spot type, street or table size where the Horse returns an illegal action or amount, falls back, or silently loses an approved upgrade. Pins one known gap by name (reported 2026-11-14 to the tournament strategy lane): in pot-limit and fixed-limit tournaments, a short-stack shove through the all-in button is not priced by upgrade 07, because `buildTournamentActionCandidates` (`HorseTournamentUtility.ts`) builds no jam candidate when `maxRaiseTo` is not numeric and the utility refuses as `baseline_not_modeled`; the same spot is priced in no-limit and when the Horse folds or calls. The pin is green only for that reason on the six listed decisions and goes red when the shove is priced, so the fix must update this law.
