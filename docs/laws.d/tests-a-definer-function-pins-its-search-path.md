# tests/a-definer-function-pins-its-search-path.law.test.ts

A SECURITY DEFINER function runs with its owner's rights but resolves unqualified names through the caller's search_path unless it sets its own, so a caller who can put an object ahead of public can hand it a table or function it never meant to touch. The law reads every migration from 2026-09-01 on and fails if a CREATE FUNCTION or CREATE PROCEDURE marked SECURITY DEFINER has no SET search_path clause, if an ALTER ... SECURITY DEFINER names a routine whose path is not pinned, or if a procedure that COMMITs or ROLLBACKs in its body carries any SET clause, because PostgreSQL then refuses its first COMMIT. It also pins the shape of migration 20261127005018: 23 invoker functions pinned to `public, pg_temp`, a verify block that proves each is pinned and that no EXECUTE grant moved, the watched guard declared, and the 14 documented exemptions left alone. Plain invoker functions are not held to a SET clause: hundreds are created without one, and some SQL helpers must stay unpinned so the planner can inline them.
