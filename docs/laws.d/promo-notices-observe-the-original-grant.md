# tests/promo-notices-observe-the-original-grant.law.test.ts

Promo notices observe original grants and accepted cash/tournament fee sources through the existing notification/push bridge. The fee observer reads one authoritative FIFO snapshot per source event without settling a grant or locking a member wallet. Received, halfway and near-completion messages have immutable per-grant receipts; a jump to ninety sends only the higher milestone. An earned unlock message requires the original final `met` closure and records the surviving principal. A manual release has an accounting receipt and never claims earned completion. In a simultaneous cross-source fee race, threshold notification timing may wait for the next fee event; the actual fee meter and cashability remain authoritative immediately. The original immutable source-review release receipt notifies exact current case holders once and refreshes recipients through the existing notification bus. No polling or repair worker supplies correctness. Daily figures use the original grant funding identity and actual return/release receipts; integrity flags use exact frozen source-grant losses. Reconciliation observes drift without fixing money. Published and actual pre-play terms agree, review holds remain separate from the 4x target, and the existing server-authorized owner/admin override requires a reason. Native PostgreSQL proof runs in the maintained promo workflow. Original paid-entry expense receipts trigger the same read-only snapshot immediately, independently of earning agreements; later canonical recognition cannot count or notify that paid fee twice. Optional fifty/ninety snapshots use a distinct nonblocking notice key per grant so competing snapshots cannot emit halfway after near completion. A busy optional snapshot waits for a later actual fee event, without a scheduled follow-up or a financial lock. Received and actual closed-met notices bypass that skip and always retain their original receipt.
