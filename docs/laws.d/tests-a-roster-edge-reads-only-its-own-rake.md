# tests/a-roster-edge-reads-only-its-own-rake.law.test.ts

The sustained-edge helper behind the union integrity sweep (`fn_union_agent_roster_sustained_edge`, 20261119063000) measured a roster's rake by expanding every rake record of the 7-day window, more than half a million rows and every contributions object, before joining the roster. That took 24 seconds per agent, and the hourly `union-integrity-sweep` cron hit its 120-second timeout at 10:33 and 11:33 UTC on 2026-11-19. This law pins the repair: the rake leg starts from the roster and reads only the rake records whose contributions name that player (the GIN index), with the same proportional share and the same union scope test; it never expands the whole window first; the function carries a high planner cost so the sweep's cheap conditions run first; it stays service-only; and the migration proves before COMMIT that every agent named by an open sweep alert is measured well inside the sweep's budget.
