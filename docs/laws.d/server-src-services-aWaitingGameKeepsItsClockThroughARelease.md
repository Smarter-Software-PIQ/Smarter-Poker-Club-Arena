# server/src/services/aWaitingGameKeepsItsClockThroughARelease.law.test.ts

2026-11-28, measured live on the 1 AM CST release 2b3b3647d3a6: all nine games owed a start read 1:05:15 AM (the first fleet cycle after the restart) as their first-owed time, because the memory behind detail.variety_owed_since was a private field of the fleet process and the fleet restarts at every release. HorseFleetManager.start() now reads, once per boot, the newest ca_horse_fleet_heartbeat row written before it started, and the first seating cycle keeps that beat's first-owed time for every game still owed (HorseVarietyFirst.carriedOwedSince into varietyOwedSince's `carried`). Nothing is carried from a beat older than VARIETY_OWED_CARRY_MAX_AGE_MS (20 minutes; measured stops are 431 to 460 seconds) or from the future, a time that is malformed, in the future or older than VARIETY_OWED_CARRY_CEILING_MS (90 days) is ignored, and a failed read carries nothing; in each case the game gets the first-cycle time as before. One read per boot and none per cycle; the carried time reaches the heartbeat and no decision (the drain's cycle outcome is identical with and without it). The same clock was lost two more ways, fixed with it: a game resting after a failed start (or carrying the cannot-start mark) left the published owed list and was forgotten, so the two 5/10 fixed-limit games never read more than minutes; varietyOwedSince now keeps the time while a game is owed, resting or marked (the set VarietyStartMemory.forgetAllBut keeps) and clears it when the game is none of those or has a player at a table (varietyOccupiedGames, the plan's own rule). And a cycle that ended before the first-owed step published {}; every beat now starts from the memory as it stands.
