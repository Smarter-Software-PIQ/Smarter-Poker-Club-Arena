# tests/a-window-migration-door-is-admitted-only-on-condition.law.test.ts

A database function created by a queued `-- @install-window: daily-maintenance` migration can only exist after that migration installs inside the 04:00 America/Chicago break, so the pre-break door check (scripts/ci/check-engine-doors-exist.mjs, via scripts/ci/window-migration-doors.mjs) admits it only as a named CONDITIONAL verdict when the creating file is on the exact target, not superseded, byte-identical to protected main and not in schema_migrations; every other missing door is refused exactly as before. Inside the break, after the admission certificate and before the engine lock, the release seal's prepare and any replacement, the host transaction re-reads pg_proc for the target's window doors (server/scripts/engine-release-window-doors.py): it waits only while this break's window install job is still running, and refuses by name, leaving the current engine running, when the install finished or no install job exists for this break with a door still missing (an unreadable signal waits inside the same budget, 2026-11-07), when pg_proc cannot be read, or when the certificate budget passes while waiting. On 2026-11-07 Engine Release run 42360536751 refused the certified e6e26ab8 eight minutes before the break because fn_cash_session_set_blind_off() and fn_lightning_blind_off_players() were created by the queued 20261106203853 window migration: a deadlock in the release order, not a missing migration.
