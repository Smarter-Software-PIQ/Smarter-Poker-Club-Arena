# server/src/engine/HoldemHotpathLatencyBitIdentical.law.test.ts

Wave 6.1 (Horse SWITCH lane, 2026-11-22): after PR #11740 eliminated the late-stage ICM spike in `phase15_node_tournament_utility`, live production telemetry showed NLH `phase15_node_reference` hitting `maxMs = 75.37 ms`. Profiling compiled production V8 JS revealed four compounding bottlenecks: (1) `scoreHoldem` fell back to array-clearing `scoreHoldemReference` for all 6/7-card Hold'em hands; (2) `simulateEquity` allocated `concat()` arrays per iteration/opponent, ran O(N) deck availability scans and linear-search swaps in `placeBandCombo` / `placeV62Combo`, re-scored the current board and allocated `Map`s inside `connectsBoard`, and sliced continuation boards; (3) `HorseHoldemCommittedPricing.holdemComboRows` recomputed hero's 7-card runout score ~48,000 times per decision (instead of once per runout) with string keys and spread arrays; and (4) `HorseHoldemValueAndCallsArePriced` (`holdemLineRange` / `holdemFillEquities`) and `HorseHoldemTournamentAllInCall` (`holdemRangeEquity`) re-scored boards and allocated per-sample arrays in tight loops. This law holds that the bitmask Hold'em scorer (`scoreHoldem`, `scoreHoldemPlus2Ids`/`Plus3Ids`/`Plus4Ids`, `straightTop`), O(1) `deckPos` NLH Monte Carlo kernel, pre-packed board-context `connectsBoard` / `buildV62StratumIndex` / `holdemLineRange` / `holdemFillEquities`, hoisted-runout `holdemComboRows`, and typed-array `holdemRangeEquity` are 100% bit-for-bit identical to the reference algorithms across normal deck, Short Deck, NLH cash, NLH tournament, and Omaha/Pineapple corpora, preserving exact RNG state and receipts with zero behavior change.

Cost bound (2026-11-24): the law also holds that the two priced decisions built on the hoisted `holdemComboRows` stay cheap, and it holds that as a quotient, not as a number of milliseconds. `expect(elapsedMs).toBeLessThan(25)` read 29.08 ms on a busy hosted runner with nothing changed (PR #11910, run 45375939160, "Server Engine shard 4/4") and passed on rerun. The decisions are now timed against the law's own independent reference enumeration of the same two boards, in the same process, in alternating rounds, fastest round of each (`measureRelativeCost`, `server/src/testing/relativeCost.ts`), and the quotient must stay under `HOTPATH_MAX_COST_RATIO`. A busy or slow machine slows both sides alike; a hot-path regression slows only the subject. The bit-identical assertions are unchanged.
