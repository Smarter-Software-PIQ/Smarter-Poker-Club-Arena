# tests/a-migration-passes-productions-ddl-guards-before-merge.law.test.ts

Incident 075013fd, 2026-11-18: two merged migrations passed every check and were refused at install by guards that run only on production: #11256's `20261118034950` by the applier's stale-pin guard (55000 `migration_left_a_stale_pin`; revert #11260, re-land #11270) and #11266's `20261118071728` by event trigger `ab_ca_money_rpc_registered` (42501, `fn_ca_bank_pending_hand_obligations` not in `ca_money_rpc_registry`; #11288). The `guards` job of `window-migrations-install-before-merge.yml` now judges every migration a same-repository pull request adds or changes (not installed, not superseded) against them before merge: a throwaway copy restored from production's schema-only archive gets production's guard rows (`ca_money_rpc_registry`, `function_body_lineage`) and production's own event triggers back (all in `public`/`smarter_private` except the wall-clock break-window guard), and each file installs through them and the applier's own `stalePinGuardSQL`; a guard refusal fails the pull request. When a file cannot install on an empty schema, production's own classifiers decide statically (stale pins against captured md5s and hex runs with `-- @stale-pin-ok`; `fn_ca_money_rpc_writes_balances` and registry order; `fn_ca_body_fingerprint` against superseded lineage). Production credentials exist only in the default-branch capture job (constant SQL, `default_transaction_read_only=on`); the job that runs the branch's SQL has no environment and no secret; an uncaptured catalog is UNKNOWN, never a pass. Native proof: `tests/unit/aMigrationPassesProductionsDdlGuardsBeforeMerge.pg.test.ts` fails both byte-exact originals and passes both fixed files through the workflow's own CLI.

Hardened after the 2026-11-18 security review: only `(pinner, current md5)` pairs leave production (the repository and its artifacts are public); what the guards read is captured in its own `capture-guards` job, so its failure makes only `guards` UNKNOWN; artifacts are downloaded by exact name; a refusal counts only when a refusing guard RAISEd it (`REFUSING_GUARDS`); and an uninstalled file is pending or history by evidence (recorded name, alias, first added to main within 14 days per `migrations-added-recently.sh`), with a time bound capped at now - 48 h, so neither a late merge with an old stamp nor one future-stamped installed version can hide a pending file (tests in `a-window-migration-installs-against-production-before-it-merges.law.test.ts`).

Hardened in Wave 2 (2026-11-20) after `20261119175941` and `20261119181500` passed empty-table rehearsal yet failed live production install inside `$probe$` blocks: before rehearsing changed migrations, `migration-guards-before-merge.mjs` idempotently seeds minimal production-like control rows (`public.ca_promo_play_through_settings` with `enforced_from IS NOT NULL`, `public.ca_mtt_admission_contract` at `unlimited-mtt-v2`, and a deterministic `public.profiles` row when present) and brackets `-- @probe-for:` blocks so unhandled `$probe$` failures fail before merge (`probe-failed`) instead of falling back to static.
