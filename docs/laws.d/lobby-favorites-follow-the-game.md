# tests/lobby-favorites-follow-the-game.law.test.ts

Dan 2026-11-05: favorites and filters are durable account preferences whose saved values change only through the account owner's explicit action or authorized account deletion. Pins that a favorite follows the logical game (a tournament schedule, an engine Sit N Go / Spin board within its owner scope, a satellite by the event it feeds, a cash_games definition), with no foreign key to any game row, an unfavorite kept as a record with its revision, and an explicit lobby_game_aliases row as the only way a recreated or renamed game inherits; that the engine's board names cannot change without an alias; that every save sends only the fields the player changed, each against a server-held revision the database checks (no device clock); that browsers can only read the three preference stores, a guard refuses every other write, and only deleting the account removes rows; that a queued change is sent only for the account that made it, after renewing an expired session; that the migration reports every legacy favorite as mapped, duplicate or unresolved and leaves legacy sources untouched; and that the native proof scripts/dev/test-lobby-favorites-postgres.sh runs in CI.
