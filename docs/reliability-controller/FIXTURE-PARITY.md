# Reliability Controller Stage B: Fixture Parity

Written 2026-11-10 (UTC). Scope: `scripts/ci/fixtures/reliability-controller-production-objects.sql`, the stand-in schema that `scripts/ci/test-reliability-controller-stage-b.py` loads before it applies migration `20261110000020_reliability_controller_stage_b.sql`.

**A passing native test is not proof of production wiring.** It proves the migration's behaviour against copies of the production objects listed below, on a throwaway PostgreSQL 17 cluster. What only production can prove is listed in section 3.

## 1. How Parity Was Checked

Mechanically, not by reading. For each object the same SQL expression was run on production (PokerIQ, project `kuklfnapbkmacvwxktbh`, PostgreSQL 17.6, read-only) and on the test cluster after the fixture loads, and the two md5 values were compared:

- Functions: `md5(regexp_replace(pg_get_functiondef(oid), '\s+', ' ', 'g'))`.
- Column lists: md5 of `attname:format_type:attnotnull:default` for every live column, ordered by name.
- Constraints: md5 of the whitespace-normalized `pg_get_constraintdef` of every CHECK, PRIMARY KEY and UNIQUE constraint, ordered.
- Trigger: `md5(regexp_replace(pg_get_triggerdef(oid), '\s+', ' ', 'g'))`.

The production hashes are constants in the test (`PRODUCTION_FUNCTIONS`, `PRODUCTION_COLUMNS`, `PRODUCTION_CONSTRAINTS`, `PRODUCTION_PUSH_GUARD_TRIGGER`). The test's first behaviour recomputes every hash from the loaded fixture and fails on any difference, so the fixture cannot drift from what was read without turning the test red. It cannot notice production changing afterwards: the hashes are a reading taken on 2026-11-10.

## 3. What Only Production Can Prove

| Contract                                                     | Why the fixture cannot prove it                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The applier installs the file                                | `scripts/ci/apply-recorded-migration.mjs` wraps the file with its history row, pin checks and a 12 second budget and sends it once; the test applies the file with `psql -f`. Lock waits on `public.operational_alert_events` under live inserts were not measured                                                                                |
| pg_cron runs `reliability-controller-tick` every minute      | The stub records the schedule row only. Execution, the session advisory lock in the command, `statement_timeout` under load and the cost of a tick on real volume are unproven                                                                                                                                                                    |
| Interplay with the six other inbox triggers                  | They are absent. Read from production: `a0_operational_alert_mirror_classify` may set `investigation_status` to `informational` before the intake trigger sees the row, and `b_operational_alert_resolved_twin_closes_firing` updates `investigation_status` only, which the intake UPDATE trigger does not listen to. That reading is not a test |
| The inbox writer's role                                      | Production inserts arrive through PostgREST as `service_role` and from pg_cron as `postgres`; the test inserts as `postgres` only. The intake trigger is SECURITY DEFINER for this reason                                                                                                                                                         |
| Messenger triggers accept the sender                         | Read from production: sender `2d1cd6c3-5700-4af9-a271-d4863fdab20d` has a profile, no block against the owner and no active restriction. `zz_restriction_social_guard` and the accounting triggers were not executed                                                                                                                              |
| The push dispatcher delivers                                 | The controller writes a `pending` row in `public.push_outbox` and mirrors that status. Claiming, device lookup, sending and the owner's phone are the existing dispatcher's work and were not exercised. No delivered or read state is recorded by the controller                                                                                 |
| The Messenger client renders the message                     | The Dock in this repository renders `content` as text. The full Messenger in World Hub was not read                                                                                                                                                                                                                                               |
| `public.fn_reliability_incident_for_owner` through PostgREST | Proven with `SET ROLE` and `request.jwt.claim.sub`; a real JWT through the API was not used                                                                                                                                                                                                                                                       |
| Classification on live traffic                               | Rules were seeded from `SOURCE-INVENTORY.md`; observe mode exists so the first live window can be reviewed before any message is sent                                                                                                                                                                                                             |
