## Root cause

`cleanupStaleProductionE2EAccounts` (scripts/ci/production-e2e-account.mjs) treated an identity as kept
only when it OWNED a retired fixture. A heads-up rematch run that died left two PLAYER identities whose
only residue is a finished entry in a retired certification club. They can never be removed, so the
certification failed on them forever.

## Fix

When the door refuses with that SQLSTATE and message, `retiredHistoryHolderClubs` reads the identity's
residue. If every entry is in a COMPLETED or CANCELLED event of a retired club, every membership is a
zero-balance player row with no agent link (or a shared cert club row), and no seat is open, the identity
is kept as a player of record and named in the log. Anything live or unreadable still fails the run.

## Proof

- With the fix: 108 of 108 pass.
- With the pre-fix `production-e2e-account.mjs` (HEAD `fbd9e5df2`): 1 fails ("keeps both players of
  record and does not fail the run"); the guard cases pass both ways.
