1. Commit the intended files with the normal repository hooks and configured Git identity. Never force-push main, bypass hooks or disable required checks.
2. Push the owned branch through the configured authenticated Git transport. If the exact commit is already on its remote branch, reuse it.
   To stop a push run, kill its process group (`kill -TERM -<pgid>`, with the pgid from `ps -axo pid=,pgid=,comm=`) and confirm with `ps` that nothing of it is left before reporting it stopped. `scripts/agent-push.sh` stops its own tree: on SIGHUP, SIGINT or SIGTERM, or when its parent process goes away, it terminates git push, the pre-push hook and their workers, prints one `STOPPED` line and exits 129, 130 or 143; a SIGKILL of its process group takes the whole tree with it, and if the helper alone is killed its watcher stops the step it was running. A `STOPPED` line is not proof that nothing landed: a stop during the push or verify phase cannot show the ref did not move, so read it (`git ls-remote origin refs/heads/<branch>`) before reporting the run stopped. The supported detached launch is `screen -dmS <name> bash -c 'bash scripts/agent-push.sh > <log> 2>&1; echo EXIT=$? >> <log>'`. The detached-launch rule is deterministic: the helper stops when its parent process goes away, from its first instant, unless it was started with `nohup` (SIGHUP ignored on entry) or with `AGENT_PUSH_DETACHED=1`, and it prints one line when that rule is off. Those two launches are not stopped when their parent goes away, but they stay in the launcher's process group, so a launcher that kills its whole group takes them too: `screen -dmS` is the launch that outlives a tool call. A `bash scripts/agent-push.sh &` whose launcher returns stops and pushes nothing.
   Heavy local work waits in one host-wide FIFO queue on the Mac (owner, 2026-11-19): `scripts/agent-push.sh` takes a slot for a push that changes an engine, database or dependency-manifest path and holds it through the pre-push hook, the hook takes one before a full local test selection, and `bash scripts/heavy-queue.sh npm-ci` installs a worktree's dependencies through the same queue with npm's download cache on the authorized SSD. Slots are the core count divided by 7 (four on the Mac Studio). `bash scripts/heavy-queue.sh status` shows who runs and who waits; `bash scripts/heavy-queue.sh run --label <text> -- <command>` queues any other heavy command, such as a full vitest run. The queue only decides when a job starts, never which checks run; a ticket whose process is gone is reclaimed by the next waiter, and a broken queue prints one warning and runs the job at once.
