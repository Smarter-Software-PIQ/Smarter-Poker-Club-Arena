# Exact EED historical runtime qualification

Run `node server/scripts/qualification/retained-original-checkpoint/qualify.mjs` from the integration repository. Local execution requires an existing external SSD `TMPDIR` outside every Git repository; GitHub Actions uses its existing `RUNNER_TEMP`. The current locked server dependencies must already exist; no client dependency installation is required. The driver never installs, fetches, starts production transport or invokes the checkpoint guard.

The driver archives only the fixed local Git object `eed06fe51dea622069c661a6213d5b031ff3a9e3` into a fresh disposable tree, links existing dependencies without writing them, compiles that historical server, and compares all 31 resulting runtime file hashes to the fixed EED pins maintained in the guard (24 previously observed deployed hashes, five Lightning dependencies independently checked in the actual process before any stop, and two exact historical ownership/release dependencies). It then copies the four preserved fixture sources into that tree and requires all seventy-four cases to execute successfully. Vitest caching is disabled. A changing guard or any compiler, hash, fixture or cleanup failure does not qualify. Every subprocess consumes the same absolute 360-second qualification budget, preserving the fixture phase's own 240-second allowance after the historical compile (66.809 seconds measured on the hosted runner) and archive/setup work; cleanup remains mandatory afterward. The enclosing process and test allow 390 and 420 seconds respectively. These isolated limits do not change production cutover budgets. The disposable tree is removed on both success and failure.

The Probe cases demonstrate actual historical stop and partial-stop behavior, including retained envelopes and bank custody; their setup is intentionally explicit. The Resume case separately enters the actual recovery path from a controller-free pending original and proves its restored capture at the physical pause gate. The Cash cases exercise the actual maintenance park writer and stop path, showing that only positively acknowledged native park state owns cash banks after stop, while held, refused or accounting-unconfirmed writes remain unsafe.

This is positive isolated historical-runtime qualification. It is not evidence that the new guard rejects an unsafe input before a source fix, that production ran this helper, that a native custody transaction committed, or that activation is certified. Guard regressions and actual provider/native/live evidence remain distinct requirements.

The sixty-six whole-guard cases compose actual EED manager/engine constructors, actor binding, recovery, maintenance pause, native park and real stop for a started pending hand, prepared sequence-zero original and ordinary cash table. Native attestation and park transport are isolated fixtures with independently bound identities/hashes; actual PostgreSQL composition remains separately required. All constructed concrete engine owners enter the supplied isolated census. Production singleton discovery and invocation are not simulated as live evidence.

The whole-guard census includes actual registered and native-stopped detached tournament managers. Unsafe detached lifecycle work, work added during an attestation await, and an omitted manager census refuse before the first stop. Four stopped-shadow Lane cases retain failed writes, unretained batches, an unmatched retained sequence and pending retention waiters. A clean later retained Lane sequence cannot be covered by an older successor capsule, and a swapped process-ownership method is refused by identity. These are isolated source-level regressions; the inspector transport separately proves discovery of both registered and detached manager prototypes.

The existing CI server shards and release preflight check out historical source objects and blobs before this bounded qualification. Git-hook repository coordinates are removed only from isolated subprocess environments so external scratch discovery uses its actual filesystem location. The hosted regression supplies an actual Git directory to preserve that boundary.

Lightning absence includes native registered/pending host collections, raw process-wide formation-gate entries, and an exhaustive concrete worker inspector census including detached pre-gate calls. The guard never expires a gate, aborts a room, or substitutes a classic-table count for this proof.

Concrete host census must also be empty: a finished host may still have an unknown settlement or downstream work. A terminal label is never positive settlement proof.

The held-permit regressions use real EED permit reservation, hand preparation and manager stop. An ordinary two-seat NLH begin response arrives after the manager fence, leaving its exact next permit unknown while the completed hand counter rewinds. A supplemental legacy PLO6 eight-seat roster reaches the deployed seven-seat deck-capacity backstop before controller/bank creation; only its owned native sleep is advanced with the fixture clock. Both a previously committed hand and a zero-bank first-hand shadow must refuse without stopping the current fleet. A covered shadow with an exact matching retained original and attested successor remains accepted. No permit cancellation, disposition or start is supplied by the guard.

The manager retirement boundary cases use actual EED GameServer retirement and native manager stop. They cover an original retirement already pending, a serial continuation beginning retirement while the guard drains, and an original retirement completing before the registry witness is published. A direct manager stop without the owning GameServer retirement remains refused before checkpoint writes. The registry witness also refuses replacement of one manager key with another already-captured manager, even when map size and its set of values appear unchanged.

Queued-renewal cases run the actual EED ownership renewal loop through its original cadence sleep. A synchronous collection stand-in delays that already-scheduled timer until the live local proof expires with no renewal Promise present. The guard may yield once to original timer processing, but accepts only an exact original GameServer retirement receipt or the completed original transition proved by the pinned native source, unchanged lifecycle/maps/generation, confirmed-release bookkeeping, absent successor/transfer work and complete physical/custody checks. A cleared Promise alone is not proof; a failed original lease release remains refused. A replaced registry object remains refused. This is not authority to renew an expired generation or call a timer manually.

The completed queued-retirement fixtures join the original scheduled sleep, its native renewal pass, and the second owner's actual retirement from another original serial continuation. They never retain a receipt artificially. Setup starts with unexpired manager and dealer authority, then shortens the manager proof at the intended collection boundary. Registered fixture cleanup always closes the native loop and joins its jobs, including when setup or a pre-cleanup state assertion fails.
