# Midway weekly creation fixture

`production-creation-contract.json` records read-only production schema and function definitions from November 7, 2026. The native harness creates both tables with their exact column types, defaults, NOT NULL requirements and every CHECK constraint. Historical NOT VALID CHECKs still enforce new rows, so they are installed as ordinary CHECKs over the empty isolated tables.

The captured creation normalizers run under their production trigger names and ordering: capacity, format assignment, mystery terms, prize arithmetic, payout depth, whole entry price, Free Buy shape, add-on stack, blind contract and short-format breaks. Their captured function definitions are independently checked against production MD5 receipts. The pre-existing original clock and owner schedule boundaries and actual earlier bounty guard remain loaded from their existing snapshots and upgraded through the exact protected migration files.

The isolated state explicitly selects the current unlimited-MTT ABI. Actual capacity and format functions read that row; the previous always-true capacity stub is removed. Empty maintenance announcement and thaw tables model an unfrozen state. Negative witnesses cover unknown ABI and real frozen admission, required clock NULL, invalid status, excessive rake, paid Free Buy, invalid mystery profile and caller-assigned format. The known NULL-clock and legacy 6 PM failures still reproduce before their fixes. All 143 canonical contracts are checked after the last included normalizer.

This is a creation-contract qualification, not a production database clone. Foreign keys, ownership/retirement/launch gates, financial bank accounting and AFTER triggers are outside this fixture. The existing affordability witness proves canonical terms precede the funding check; it does not prove real bank coverage. Exact cancellation is represented by a refusing stub to prove failure rollback and claim preservation. No wallets, production players, hands or financial ledgers are copied or replayed. The captured full BEFORE INSERT inventory makes the included and excluded boundaries reviewable.
